## Lessons Learned

1. **A dramatic diagnostic number is not automatically confirming evidence for the hypothesis you're testing — weigh it equally as evidence you made a mistake.** This is a sharper, more specific version of "don't ship a guessed query with more confidence than it deserves" (from this session's own prior lesson): the danger isn't only in the *query itself* looking too polished, it's in *your own diagnostic output* (a big number, a clean match, a dramatic contrast) feeling like proof when it might just be measuring your own error.
2. **`ORA-00942` (or any "object does not exist" error) from a service account that's known to work for *some* queries against the same schema is a strong signal to check privileges before assuming the object is genuinely missing** — especially when a different, already-working query in the same codebase references the same schema successfully.
3. **When a recurring file-corruption bug survives being asked about directly, switch diagnostic tactics instead of re-asking the same question** — an unanswered "what program are you using" twice in a row means the question itself isn't landing; ask for evidence instead (a screenshot, a byte count, a hex dump of the specific broken region) rather than repeating it a third time.
