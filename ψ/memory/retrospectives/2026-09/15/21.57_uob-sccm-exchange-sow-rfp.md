## Lessons Learned

- **"Exploratory, skip the ceremony" framing must be re-evaluated the moment stakes change, not carried on autopilot.** เมื่อ user แปะเอกสารจริง (RFP/สัญญา/ข้อมูลภายนอกที่มีผลผูกพัน) เข้ามากลางบทสนทนาที่เริ่มแบบ hypothetical ต้อง pause แล้วถามตัวเองใหม่ว่างานนี้ยังนับเป็น "pure investigation" อยู่ไหม ถ้าไม่ใช่แล้ว (มีเดดไลน์จริง มีเงินเดิมพันจริง) ต้อง apply SDLC gate/second-opinion rule ที่ CLAUDE.md กำหนดไว้ ไม่ใช่ปล่อยกรอบเดิมลากยาว
- **เมื่อสร้างเอกสารสองชิ้นที่เกี่ยวโยงกัน (generic draft → ตามด้วยของจริงที่ raise ข้อมูลใหม่) ต้อง reconcile หรือ flag การ mismatch อย่างชัดเจนทุกครั้ง** ไม่ใช่แค่เสนอครั้งเดียวแล้วปล่อยผ่านถ้า user ไม่ตอบรับ — ต้อง track ว่ามี artifact ไหนที่ stale อยู่ และเตือนก่อนปิด session
- **RFP/สัญญาจริงคือ ground truth ที่ต้อง anchor คำแนะนำทั้งหมดไว้กับตัวเลข/คำศัพท์ในนั้นโดยตรง** — แยกให้ชัดระหว่าง "ambiguous ต้องถาม client" (เช่น SCCM version string, scope boundary) กับ "เดาไม่ได้ต้องหาเอง" ไม่ผสมสองอย่างนี้เข้าด้วยกัน
