## Lessons Learned

- **When a proxy/network fix works on one machine but not an identically-configured one, diff the
  two machines' actual resolution paths before proposing a second fix** — Windows PowerShell
  5.1's `Invoke-RestMethod` resolves proxy via WinINET (per-user registry), not WinHTTP, so a
  `netsh winhttp set proxy` command can run successfully and change nothing relevant; the
  authoritative diagnostic is comparing against a machine where the call already succeeds, not
  guessing at which proxy subsystem is in play.
- **Don't change a shared service account to fix an unrelated symptom without checking what else
  that account is relied on for.** The gitlab-runner service account on a Windows box wasn't just
  running CI jobs — it was also the identity `Start-WebAppPool`/`Stop-WebAppPool` executed as;
  swapping it to fix a proxy issue silently broke IIS control, a dependency that wasn't visible
  until the next deploy failed.
- **A GitLab instance-wide SSRF-protection setting ("Allow requests to the local network from
  webhooks and integrations") is OFF by default and silently rejects webhook URLs pointing at
  `127.0.0.1` or the server's own IP with a generic `Invalid url given` error** — worth checking
  this setting first, before assuming the webhook target itself is misconfigured, whenever a
  self-hosted GitLab's own webhook creation fails against a same-box target.
- **On a self-hosted GitLab CE instance, "Approve" exists as a UI action in Community Edition but
  enforced/required approval rules are Premium-only** (confirmed via 404s on the relevant API
  endpoints) — plan team workflows around approvals as a social/recorded convention, not a
  technical gate, unless the instance is licensed Premium+.
- **A `curl`+Personal-Access-Token workflow against the GitLab REST API is a fully viable
  substitute for an entire multi-day session when browser automation never connects** — this
  isn't a fallback to apologize for; treat it as the default interaction mode for GitLab
  administration tasks rather than something to keep retrying browser access to unblock.
