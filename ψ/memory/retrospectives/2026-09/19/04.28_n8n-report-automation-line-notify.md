## Lessons Learned

- **In n8n, any field containing `{{ }}` requires an explicit Fixed→Expression toggle before the
  mustache evaluates — this is not automatic just because the text looks like an expression.**
  Left in Fixed mode, the literal template text (sometimes with a leading `=`) is used as-is, and
  the failure is usually silent (wrong/undefined value, not an obvious syntax error) until you
  trace it back. Check this first whenever an n8n node field produces unexpected output.
- **A node that returns a wholly new object (file-read nodes, HTTP Request nodes, Code nodes with
  a fresh `return`) overwrites `$json` for everything downstream — it does not merge with
  upstream fields.** Reference the originating node explicitly (`$('Node Name').first().json.x`)
  whenever there's an intermediate transform node between the value's source and where it's used.
  This class of bug is invisible in a short smoke test that skips the intermediate node, and only
  shows up once real, full-chain data is used — always do at least one full-chain test with real
  data before declaring a workflow done, even if a shorter test already passed.
- **When a chat-hosted code block or JSON snippet needs to be copy-pasted into a separate
  application's text field, don't rely on `\n` escape sequences surviving the paste — word-wrapped
  display text can silently become real embedded newlines in the destination field.** If the
  destination is JSON or another format where raw newlines are invalid, prefer a non-newline
  separator (a `|`, a distinct delimiter) over spending multiple retry cycles trying to paste
  more carefully. This is the same underlying failure mode as RDP-paste corruption seen earlier
  in this project's history, just via a different clipboard path — recognize it by symptom
  (correct-looking source, garbled destination) rather than needing the exact same trigger to
  spot it.
