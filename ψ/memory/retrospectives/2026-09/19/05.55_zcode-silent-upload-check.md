## Honest Feedback

1. **การอ่านโค้ดใน bundle ที่ minify เปลืองรอบ** `grep` (ugrep) พังสองครั้งเพราะ pattern `.{200}` เกิน complexity limit ต้องย้ายไปใช้ python; ชื่อตัวแปรย่อชนกัน (`Ke`, `YTe` ไปจับฟังก์ชันของ LSP/Zod ที่ไม่เกี่ยวเลย) ทำให้ output ท่วมและอ่านยาก ควรค้นด้วย string เฉพาะที่ไม่ถูก minify แล้วค่อยขยายบริบท ตั้งแต่แรก
2. **zsh ไม่แยกคำจากตัวแปร** `F="a b c"; grep "$F"` ในสแกน secret เลยล้มเหลวหนึ่งรอบ (ต้องใช้ array) เล็กน้อยแต่ซ้ำได้ง่ายในทุก session ที่ shell เป็น zsh
3. **`/learn` skill ไม่เข้ากับสถานการณ์นี้** skill สมมติว่าเป็น GitHub repo (ghq clone + `origin/`) และบอกว่าให้ commit docs ส่วนไฟล์จริงของ repo นี้ gitignore `ψ/learn/` ทั้งโฟลเดอร์ และ Golden Rule 1 ห้าม `--force` เลยต้องหยุดถามมอสหนึ่งรอบก่อน commit ได้ ขาดการชี้ชัดใน CLAUDE.md ว่าจะจัดการ `ψ/learn/` ยังไง

## Lessons Learned

1. **ชื่อบนหน้าจอต้องอ่านจากตัวโปรดักต์เอง ไม่ใช่จากบทความ** บทความ/โค้ดใช้ชื่อภายในหรือชื่อที่ผู้เขียนตั้งเอง ก่อนเขียนอะไรที่ให้คนอื่นไปหาปุ่มเอง ให้ดึง label จริงจาก i18n/UI ก่อน
2. **คำว่า "ไม่มีตัวกั้น" ต้องพิสูจน์ด้วยการนับครบ ไม่ใช่ดู N ตัวแรก** ค้นทุก occurrence, จำแนกทีละอัน (schema / migration / UI / logic) และรายงานตัวเลข "ทั้งหมดกี่อัน จำแนกยังไง" ถ้าสคริปต์มีเพดานจำนวนผลลัพธ์ ผลที่ได้พิสูจน์การมีได้ แต่พิสูจน์การไม่มีไม่ได้
3. **แยกระดับหลักฐานสามขั้นเสมอ** (โค้ดมีอยู่ / ทำงานบนเครื่องนี้จริง / รู้สาเหตุ) ผลเช่น "โค้ดมี แต่เครื่องนี้ไม่ถูก trigger และยังไม่รู้เพราะอะไร" ห้ามถูกย่อเป็น "ปลอดภัย" หรือให้เหตุผลปลอบใจ (เช่น "เพราะใช้ Claude") โดยเฉพาะในโพสต์สาธารณะ
4. **มาตรการป้องกันที่ทดสอบผ่านไม่เท่ากับปลอดภัย** `touch` ขึ้น Operation not permitted พิสูจน์แค่ว่าล็อกทำงาน ยังไม่ได้พิสูจน์ว่ากันของจริงตอนแอปรัน; ชั้นที่แข็งกว่า (sign out) ต้องบอกก่อนเสมอ
