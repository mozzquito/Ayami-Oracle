## Lessons Learned

- When delegating a task to a CLI agent (zcode/agy/grok) that requires it to *execute*
  code and report real results — not just describe a plan — explicitly choose a mode that
  permits file writes/execution (e.g. agy's `--mode accept-edits`, scoped to a scratch
  directory) rather than defaulting to the safest-sounding "plan/review" mode. A
  read-only mode on an execution-shaped task doesn't fail loudly; it just produces a
  plan and waits for approval that a single non-interactive call can never give it. State
  explicitly in the prompt that there is no follow-up turn to confirm a plan with.
- When a symbol/strategy selection process is later found to have relied on
  survivorship-biased or cherry-picked backtest numbers, don't just fix the specific
  symbols flagged — re-check every *rejected* alternative from that same original
  selection process against both the short recent window AND the full available history
  before adding any of them back. A candidate that looks good only in a short recent
  window and bad over full history is exactly the same trap in reverse.
- A platform's own "secure conversation" or "message queue" API bridge can be
  desynchronized from what a human sees and does through its UI — a message can appear
  fully resolved/replied in the UI while an API-side `verify` call still reports it as
  perpetually pending. When an automated bridge to a third-party agent platform gets
  stuck this way with no clean recovery call available, creating a fresh conversation
  thread (accepting the loss of prior context) is a reasonable, low-cost way to
  unblock, rather than retrying the same locked call.
- For cron/scheduled cloud jobs (Railway or similar), don't wait for the next scheduled
  tick to verify a deploy — check whether the platform's API exposes a manual
  "trigger one execution now" mutation (Railway: `deploymentInstanceExecutionCreate`,
  keyed by ServiceInstance ID, not Service ID) and use it immediately after deploying,
  the same way `deploymentInstanceExecutions` is already used to inspect past runs.
