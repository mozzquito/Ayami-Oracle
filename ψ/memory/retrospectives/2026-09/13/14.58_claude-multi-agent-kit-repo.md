## Lessons Learned

- เมื่อสร้าง artifact ที่จะ publish สู่ public/external ที่คนอื่นเห็นได้ทันที (public GitHub repo, public artifact, ฯลฯ) — ตัดสินใจเรื่อง naming/license/attribution ควรถาม user ยืนยันก่อน publish จริง ไม่ใช่แค่ถาม visibility (public/private) เพียงอย่างเดียว. Irreversibility ไม่ได้อยู่ที่ "จะ push ไหม" เท่านั้น แต่อยู่ที่ "เนื้อหาที่จะ push คืออะไร" ด้วย.
- เมื่องานสร้าง repo/ไฟล์ใหม่เกิดขึ้น**นอก**ตัว repo หลักที่ session ทำงานอยู่ (external directory) การเขียน retrospective จะพึ่ง `git log`/`git diff` ของ repo หลักไม่ได้เลย — ต้องพึ่ง conversation memory + list ไฟล์ที่สร้างจริงในโฟลเดอร์ปลายทางแทน. คุมด้วยการเช็ค `git status`/`git log` ของ repo ปลายทางจริงแทนที่จะ assume จาก repo ที่ session เปิดอยู่.
- Consult zcode/agy ตาม SDLC gate แม้งานจะดู "เล็ก" (README + template files) ยังให้ feedback ที่ actionable จริง (settings.json permission gap) — ไม่ควรข้ามขั้นตอนนี้แค่เพราะรู้สึกว่างานตรงไปตรงมา.
