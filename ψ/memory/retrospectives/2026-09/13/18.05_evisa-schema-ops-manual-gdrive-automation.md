## Lessons Learned

1. **Never hand over a reconstructed production query as a clean "ready to test" block when the reconstruction is pure guesswork about business semantics** (date-diff basis, derived-vs-stored classification columns, etc.). It reads exactly as credible as a verified query, and the reader has no way to tell the difference from formatting alone.
2. **A working interactive/browser session on a Windows box behind a corporate proxy never implies a separate binary will inherit that proxy.** WinINET (browser, PowerShell's classic web cmdlets) and a standalone process's direct-connect attempt are different code paths — this is now the second documented session in this project where that exact mismatch caused a debugging detour before being recognized (see `ψ/memory/learnings/2026-09-08_wininet-vs-winhttp-proxy-powershell.md`).
3. **When an install-policy wall rules out the obvious tool, reach for a second/third-model consult (zcode/agy) *before* exhausting more of one's own next-best guesses, not after.** The winning answer here (Apps Script Web App, zero installs) came from that consult, not from iterating alone through rclone → SMB relay.
4. **A "พักไว้ก่อน" (paused) item needs an explicit re-surfacing trigger, or it silently becomes closed by default.** Two real findings and one open diagnostic thread went cold this window purely because nothing prompted me to check back — worth actively re-raising deferred items when later work touches the same ground, rather than waiting to be asked.
