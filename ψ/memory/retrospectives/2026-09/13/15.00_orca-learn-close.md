## Honest Feedback

Three friction points specific to this session: (1) The default 2-minute Bash timeout was too short for cloning a 701MB repo (`ghq get` for stablyai/orca), forcing a kill-and-retry-in-background cycle that cost an extra round trip — for `/learn` on external repos, sizing the clone attempt for background-from-the-start would have avoided this entirely. (2) I made the ScheduleWakeup polling mistake described above — minor, self-corrected, but it's exactly the failure mode the tool's own docs call out by name, so it shouldn't have happened at all. (3) The multi-week dormant gap meant zcode's background bash output file was garbage-collected from `/private/tmp` by the time the session resumed, silently losing one of the two second-opinion cross-checks the user explicitly asked for — agy's survived only because it happened to print inline into the conversation transcript before the gap, not because of any durability guarantee. That's a real gap: background delegation to external CLI agents (zcode/agy) has no persistence guarantee across a session boundary, unlike the Haiku subagents whose file *outputs* (not their transcripts) survived because they wrote directly to the vault.

## Lessons Learned

- For `/learn` (or any `ghq`/`git clone`) on a repo of unknown size, start the clone in the background immediately rather than attempting it in the foreground first — large repos routinely exceed the default 2-minute Bash timeout, and the retry cycle is pure waste.
- Never schedule a short-interval `ScheduleWakeup` to poll work already tracked by the harness (`Bash run_in_background`, `Agent`) — the completion notification fires on its own; a manual poll wakeup for that same work is redundant by construction, not just occasionally unnecessary.
- When a background subagent/task notification says "killed" or "stopped" after a session gap, don't treat that as proof the work was lost — check the actual output artifact (file on disk, not the task transcript) before deciding whether to redo it.
- Delegating to external CLI agents (zcode/agy) via backgrounded shell calls has no output durability across a session/process boundary — if the delegated work matters and the session might close before it's read, capture the result into a durable file immediately rather than relying on stdout capture surviving until the next turn.
