## Lessons Learned

- Any skill instruction that says "run `ls -t` to find the current session's `.jsonl`" is unsafe in a project where multiple Claude Code sessions can run concurrently in the same working directory — always prefer `$CLAUDE_SESSION_ID` (or the scratchpad-path fallback) first, and treat `ls -t` as a last resort only. This applies to every skill that does session detection, not just `/rrr` — check `/forward` and any other skill with a similar snippet.
- Before committing files found sitting uncommitted in a shared working tree, check whether they were deliberately left that way by a prior session (search recent handoffs/outbox files for the filename) rather than assuming they're either "safe to commit" or "abandoned." A prior session's own handoff note is often the fastest way to learn *why* something was left uncommitted.
- When multiple concurrent agent sessions operate on the same git working directory, treat any file under active write (outbox, focus files, shared logs) as something that can change between your read and your next read — re-read before editing rather than assuming your last read is still current, and don't treat a mid-session diff to a shared file as corruption.
