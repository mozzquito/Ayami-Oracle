## Lessons Learned

- Before writing "X should be a no-op" or any similarly confident claim into a document another person will read (a PR body, a handoff), run the actual check first — a git merge --no-commit costs one command and catches what inference cannot.
- When `gh pr list` is scoped to a non-default-branch repo, always pass `--repo owner/name` explicitly, or a real open PR can silently read back as `[]`.
- A handoff or pending-list is a point-in-time snapshot; a later "Update" section appended to the same file can supersede an earlier line in the same document — read to the end before treating the first list as current.
- Explicit authorization for an action doesn't guarantee the harness will permit it when the action's payload includes sensitive-looking content (internal hostnames/IPs); expect this and have a "report and stop" path ready rather than assuming a denial means "try a different tool."
