## Honest Feedback

1. **CSS ordering ต้องตรวจทานก่อน ไม่ใช่หลัง** — อ่าน artifact-design guidance มาแล้วรอบเดียว แต่ตอนพิมพ์โค้ดจริงกลับสลับลำดับ
   `@media`/selector ผิด ทั้งที่ guidance เพิ่งอยู่ตรงหน้า นี่คือความเสี่ยงเวลาต้องพิมพ์ CSS ยาวๆ ทีเดียวโดยไม่ทวนแต่ละ block
   ทีละอัน — ควรใช้เวลา diff กับ pattern ต้นแบบก่อนเขียนยาว ไม่ใช่หวังพึ่ง self-review ตอนท้ายอย่างเดียว
2. **`agy -p` ช้ากว่า `zcode -p` มากในงานนี้** — zcode ตอบใน foreground ทัน (<180s) แต่ agy เกิน timeout ต้อง fallback
   ไป background แล้วรอ notification ทำให้จังหวะ "ปรึกษาคู่ขนานแล้วสรุปพร้อมกัน" สะดุดเล็กน้อย ต้องส่งข้อความบอก user
   ระหว่างรอแทนที่จะได้สรุปทั้งคู่พร้อมกันในทีเดียว
3. **Context โตเร็วกว่าที่คาด** — งานสองชิ้น (AYAMI-MANUAL.html ยาว ~900 บรรทัด + MOSS-MANUAL.html) ทำให้ context
   ทะลุ warn threshold (150k) ตั้งแต่กลางงานที่สอง และแตะเกือบ 190k ตอนเริ่ม /rrr — เขียน HTML แบบยาวในบทสนทนาเดียว

## Lessons Learned

- เวลาต้องเขียน CSS custom-property dark-mode ตาม artifact-design contract ให้ก็อป pattern ต้นแบบ
  `@media (prefers-color-scheme: dark){ :root:not([data-theme="light"]){...} }` มาวางตรงๆ ก่อน แล้วค่อยเติมค่า
  อย่าพิมพ์โครงสร้างเองจากความจำแม้จะเพิ่งอ่านมา — ลำดับ media/selector ผิดจะทำให้ dark-mode เงียบๆไม่ทำงานในบาง renderer
- `agy -p --mode plan` มีโอกาสเกิน foreground timeout (180s) ได้แม้เป็นคำถาม design ธรรมดา ไม่ใช่แค่ task เขียนโค้ดหนักๆ —
  เวลาเรียก zcode+agy คู่ขนาน ให้เผื่อใจว่า agy อาจต้อง background แล้ววางแผนสื่อสารกับ user ระหว่างรอไว้ล่วงหน้า
- เมื่อ user เอ่ยชื่อเครื่องมือเฉพาะ (เช่น jev) มาสำหรับงานที่อยู่นอกขอบเขตจริงของมัน (ตาม SKILL.md ของมันเอง) ให้อธิบาย
  เหตุผลที่ข้ามอย่างตรงไปตรงมาแทนที่จะฝืนยัดคำถามเข้าไปให้ได้ผลลัพธ์ที่ไม่มีความหมาย — โปร่งใสสำคัญกว่าความครบถ้วนผิวเผิน
