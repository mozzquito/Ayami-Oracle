## Lessons Learned

- When a repo has multiple git remotes, `gh pr list` / `gh issue list` can silently resolve to the wrong one — always check `git remote -v` (or `gh repo view`) before trusting their output, especially before writing "cleanup" items into a handoff/plan that a future session will act on unquestioned.
- Vault files (`ψ/`) shared across concurrent agents/sessions on the same repo should be treated as shared mutable state: re-read before referencing content you wrote earlier in the same turn if enough time/tool calls have passed for another writer to have touched it, and don't assume exclusive ownership just because "this is my session."
- When asked to bulk-commit an undifferentiated pile of untracked files, partition by provenance (tool-generated sync noise vs. hand-authored content vs. build artifacts) rather than an all-or-nothing `git add -A` — the CLAUDE.md rule against `-A` exists precisely for piles like this.
