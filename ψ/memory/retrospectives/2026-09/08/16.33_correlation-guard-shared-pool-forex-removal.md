## Lessons Learned

- When a live production system's cron/scheduled logs return empty from the CLI's
  direct time-range flags (`--lines`, `--since`), don't conclude "no logs exist" —
  query the platform's execution/deployment history API first to find the actual
  execution or deployment ID, then fetch logs scoped to that specific ID. Time-range
  log queries and per-execution deployment tracking can be genuinely disconnected
  features on the same platform, especially for job-style (not always-on) services.
- Before reporting on "the current behavior" of a just-deployed change, cross-check the
  actual deployment timestamp against the timestamp of the event being investigated —
  a deploy landing between two scheduled runs means the run in question may have
  executed under the *previous* version of the logic. Don't assume a user's framing of
  "since deploying X" is automatically accurate; verify which build was actually live
  at the timestamp in question before reporting, even when confirming their framing
  would be the easier answer to give.
- A correlation/resource guard with a total cap plus a sub-cap on one dimension (e.g.,
  "crypto ≤ 4 of a shared 5") only guarantees the *other* dimension a minimum share in
  aggregate over time — it does not guarantee that dimension gets first claim on a
  shared slot within any single evaluation pass if list/processing order still favors
  the capped dimension. First-come-first-served bias inside a shared pool is a distinct
  failure mode from a per-market cap being exceeded, and needs its own documentation or
  fix, not just "the sub-cap already handles it."
- When a user reports a change in real-world circumstances (capital changed, now
  trading exclusively in one market) that implies a system change, don't infer the
  scope of the requested change from the report alone — ask what specifically should
  happen to existing state (open positions, notifications, background tracking) before
  implementing, even when the "obvious" interpretation seems likely correct.
