mostly warranted rather than churn: มอส was genuinely exploring which convention fit (hardware

[→ AGENT DECISION] Partway through, while waiting on a background research task, I called
ScheduleWakeup to poll for it — a tool explicitly scoped to `/loop` dynamic-mode sessions, not a
plain conversation. I caught it in the same turn (rereading the tool's own description made the

correctly all session up to that point, which makes the lapse more a momentary slip than a
misunderstanding.

The most useful discipline I held onto was treating zcode/agy output as claims to verify, not facts
to relay — twice this paid off directly: once when agy invented two Comptroller-General circular
numbers with plausible-sounding content that didn't match what the real circulars say, and once
near the very end when zcode flagged a real SendGrid feature (Sender Engagement Quality Score) as
fabricated, when in fact zcode had just checked a wrong, guessed URL path. Both would have gone
into a government procurement document as either a false legal citation or a false negative if I'd
passed them through unchecked.

## Honest Feedback

**zcode reliability was inconsistent in a way that cost real time.** Multiple delegated tasks hit
`[1302] Rate limit reached for requests` and appeared to fail outright in the tool result, but at
least twice (the SaaS-datasheet-convention research, and the final Wayama-datasheet fact-check) the
underlying process had actually kept retrying and produced a full, useful answer by the time the
task-notification fired — meaning a result that looked like total failure at first glance needed a
second look at the full output file before I could tell whether to treat it as empty or substantive.
That ambiguity is exactly the kind of thing that would cause a wrong "no output, moving on" call if
not checked carefully.

**agy hit a hard permission wall with zero graceful degradation.** One delegated fact-check pass
returned nothing but `"a tool required the read_url permission that headless mode cannot prompt
for, so it was auto-denied"` — a clean failure message, but it meant an entire planned
cross-verification pass had to be redone by hand via direct WebSearch, with no partial credit from
the attempt.

**Chrome extension screenshot capture failed consistently across unrelated pages** ("Script
injection timed out after 5000ms") after mid-session reconnection, blocking the originally-planned
approach of assembling a reference-document bundle from genuine screenshots of Twilio's official
pages (the approach the real Thai TOR text explicitly sanctions: printouts with URL + date). I
pivoted to a written/verified-text compilation instead of retrying the capture indefinitely, which
was the right call per the "don't loop on repeated browser failures" guidance, but it meant the
final artifacts are compiled text rather than literal screenshots — a real difference in
evidentiary weight that มอส should know about if this is used in an actual bid.

## Lessons Learned

- **When a SaaS/cloud vendor is proposed against a TOR written for hardware/on-prem procurement,
  "no formal datasheet exists" is the expected state, not a documentation gap** — real Thai
  government TOR text (สตง. ข้อ 15.2, a GISTDA cloud-service TOR) explicitly treats a catalog/
  datasheet as conditional ("ถ้ามี") and instead mandates a self-authored compliance-matrix table
  with page-number references into whatever official material *is* available. Build that matrix
  first; don't chase down or fabricate a datasheet-shaped document to fill a gap the TOR itself
  doesn't require filled.
- **A reviewed document's own internal consistency matters as much as any single claim's
  correctness** — the same Wayama Tech document stated a tier caveat correctly in prose ("EU data
  residency... higher entitlements") while dropping it in a summary table row ("Data Residency
  (EU): Included"). A procurement evaluator skimming only the table sees the wrong thing even
  though the fuller text right above it is accurate. When reviewing compiled vendor/reseller
  documents, check that every qualifier stated once is also present everywhere else the same fact
  appears.
- **Treat a subagent's negative finding ("this doesn't exist," "this is fabricated") with the same
  skepticism as a positive one** — verify the check itself, not just the conclusion. zcode's claim
  that "Sender Engagement Quality Score" was a fabricated feature traced back to checking a single
  guessed URL that 404s, while the actual documented feature lived at a different real path. A
  wrong negative is just as capable of corrupting a procurement document (as a false correction) as
  a wrong positive is (as a fabricated citation).
