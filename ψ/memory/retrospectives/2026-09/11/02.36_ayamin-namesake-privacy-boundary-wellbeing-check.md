## Lessons Learned

- **การปฏิเสธ privacy-sensitive request ต้องยึดที่ "การกระทำ" ไม่ใช่ "ตัวมือที่ทำ"** — เมื่อผู้ใช้เปลี่ยนจากขอให้ Claude ทำเองเป็นขอให้ agent อื่น (agy/zcode/grok) ทำแทน คำตอบต้องเหมือนเดิม เพราะปัญหาอยู่ที่ผลลัพธ์ (ไฟล์ profile ของบุคคลจริง) ไม่ใช่ว่าใครเป็นคนสร้างมันขึ้นมา — การยอม delegate ให้ agent อื่นทำสิ่งที่ตัวเองปฏิเสธคือการหาทางลัดผ่านหลักการ ไม่ใช่ทางแก้
- **เปลี่ยน framing ของ request ไม่เท่ากับเปลี่ยนแก่นของ request** — "เก็บพฤติกรรมไปใช้กับ AI" กับ "บันทึกวิเคราะห์ลง .md ให้ AI อ่าน" มีแก่นเดียวกันคือสร้าง dossier ถาวรของบุคคลจริงที่ไม่ยินยอม การลด scope (ทุกโพสต์ → 1 เดือน) ก็ไม่ได้เปลี่ยนแก่นนี้ — ต้องแยกให้ออกระหว่าง "ลด scope ของการกระทำที่มีปัญหา" กับ "เปลี่ยนการกระทำที่มีปัญหาเป็นการกระทำที่โอเค"
- **wellbeing-check ที่ถูกต้องคือดูข้อมูลชั่วคราวในบทสนทนา ไม่ใช่บันทึกถาวร** — เมื่อจุดประสงค์เปลี่ยนเป็นมนุษยธรรมจริง (เช็คว่าเพื่อนไหวไหม) การช่วยดูเนื้อหาสดๆ เพื่อประเมินความเสี่ยงแล้วช่วยร่างข้อความให้เจ้าตัว (มอส) ไปทักเองเป็นแนวทางที่สมดุลระหว่างการช่วยเหลือกับการเคารพความเป็นส่วนตัวของบุคคลที่สาม — ดีกว่าทั้งการปฏิเสธเฉยๆ และการสร้างรายงานวิเคราะห์แบบเป็นทางการ
