## Lessons Learned

- **A design doc's claim that something was "verified" or "confirmed against the actual X" is a claim, not a substitute for checking X yourself** — even well-written, specific-sounding verification claims in a doc should be spot-checked against the live source (an installed package's type definitions, in this case) before being relied on, especially when you're independently reviewing the same work rather than the same session that wrote the doc.
- **When multiple Claude Code sessions (or other agents) can operate on the same or sibling repos concurrently, re-check actual repo state (git log, git status) immediately before acting on a "pending task" pointer (a focus file, a task list) — the pointer can go stale between when it was written and when you act on it**, not just from human edits but from a different session completing the same work in the meantime.
- **After a long idle gap in a resumed session, treat all held context about "current state" as expired and re-derive it from files, not from what you last observed** — the correct instinct isn't "how much has probably changed" but "read fresh, then compare."
