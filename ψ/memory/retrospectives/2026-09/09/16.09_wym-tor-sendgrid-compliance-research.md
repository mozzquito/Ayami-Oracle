## Honest Feedback

Three friction points from this session, specific to what happened here (not generalized advice):

1. **Reactive rather than proactive link verification.** The user had to explicitly ask for
   working references twice across the conversation before I started running `curl -I` against
   every URL before including it. Once established, it became routine and cheap — the friction
   was in not defaulting to it from the first deliverable.

2. **A large, mostly-irrelevant memory read early on.** Reading `project_evisa_wayama.md` in full
   (877 lines, only got through 523 before truncation) to check for TOR/SendGrid context cost a
   real context slice for close to zero payoff — the file turned out to be almost entirely SQL
   query history for the eVisa database, unrelated to the email procurement question.

3. **The task boundary shifted several times without a clean handoff point** — web research →
   artifact → xlsx review → xlsx correction → feature list → xlsx append. Each pivot was
   reasonable given what the user asked in the moment, but a mid-session recap of "here's what's
   been delivered so far" might have helped both of us track state across ~6 distinct sub-asks in
   one continuous thread, especially once the deliverable split across two mediums (web artifact +
   spreadsheet).

## Lessons Learned

- **Verify every citation URL with an HTTP check before shipping it, by default — not only when
  asked.** Compliance/procurement research carries real consequences if a cited reference is
  dead or wrong; build `curl -I` (or equivalent) into the research step itself, not as a
  follow-up remediation.
- **When comparing a vendor's marketing/pricing figures against a spec's numeric requirement,
  check the unit before the number.** "300,000 emails/month" and "200,000 emails/day" look like
  the same kind of claim but are off by roughly 20x once normalized — this is a recurring trap in
  TOR/RFP compliance matrices where vendors quote whatever denomination flatters their plan tier.
- **Before reading a large existing memory/notes file end-to-end for context, grep for the
  specific keyword first.** A multi-hundred-line project memory file accumulated over weeks often
  covers many unrelated sub-threads; a targeted search costs one tool call and avoids burning
  context on an irrelevant full read.
