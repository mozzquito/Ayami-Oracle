## Honest Feedback
1. **zsh สะดุดซ้ำๆ:** `"$O[server,dev]"` ถูกตีเป็น subscript (uv ฟ้อง PEP508 ว่างเปล่า), ตัวแปรเก็บคำสั่ง `$P` ไม่ถูกแยกคำ, `--include=*.py` โดน glob, และเรียกเครื่องมือขนานแล้ว cwd ไม่ตรงที่คิด ทำให้เสียหลายคำสั่งกับไฟล์ smoke test ที่ไม่ถูกสร้าง
2. **เครื่อง 8 GB ที่ swap ไปแล้ว ~5 GB:** ทุกอย่างที่หนักเปราะ ต้องมาไล่ดู memory pressure/jetsam และเลือก fp32/MPS/CPU ระหว่างทาง ควรตรวจก่อนเริ่มไม่ใช่หลังพัง
3. **ตัวสรุปของเครื่องมือดึงเว็บเขียนโดยโมเดลเล็กและผิดบางจุด** (เวอร์ชัน Python) ทุกรายละเอียดที่ใช้ตัดสินใจจึงต้องไปตรวจกับไฟล์ต้นฉบับซ้ำ ต้นทุนเวลาสูงกว่าที่คิด และรีวิวจาก zcode/agy ต้องตรวจซ้ำอีกชั้น (ผิดทั้งคู่คนละข้อ)

## Lessons Learned
(รายละเอียดใน `ψ/memory/learnings/2026-09-21_read-the-log-before-retrying-a-struggling-service.md` และ `2026-09-21_openthai-systemone-local-eval.md`)
1. เมื่อคำขอหมดเวลากับบริการที่เริ่มต้นหนัก ให้อ่าน log และสถานะหน่วยความจำก่อน retry — retry ทวีโหลดได้; ทำการเริ่มต้นหนักให้เป็นแบบโหลดครั้งเดียว (eager) แล้วให้ประมวลผลทีละคำขอ
2. รันโมเดล/โค้ดของบุคคลที่สามเมื่อ diff กับซอร์สที่อ่านแล้วเท่านั้น, ตรึง revision + ตรวจ hash, ติดตั้งใน venv แยก, เลี่ยง `trust_remote_code` ถ้าใช้แพ็กเกจที่ตรวจแล้วโหลดแทนได้
3. คำอ้าง benchmark ของผู้ขาย: ดูว่า "zero-shot" หมายถึงอะไร, ข้อมูลเทรนซ้อนกับชุดข้อมูลที่ทดสอบหรือไม่, ตัวเลขคู่เทียบมาจากไหน แล้ววัดเองด้วยชุดของเราแบบไม่แก้คำถามเพื่อความแฟร์
4. สรุปที่โมเดลเล็กเขียน (เครื่องมือดึงเว็บ) และรีวิวจากเอเจนต์อื่นต้องตรวจกับไฟล์ต้นฉบับก่อนใช้ตัดสินใจ
