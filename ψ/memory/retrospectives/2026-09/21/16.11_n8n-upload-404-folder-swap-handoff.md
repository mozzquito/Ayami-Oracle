## Lessons Learned

- **When two statements conflict about a production mapping (which ID belongs to which job), reconcile against independent history before writing it into config.** A later, more convenient answer (a multiple-choice pick) does not override an earlier labelled one, or the original setup record. Ask for the tie-break or check the history; do not just take the newest.
- **A retry loop that swallows the caught exception turns a diagnosable error (HTTP 404) into an opaque "FAILED after N tries".** Any unattended script should print the caught message on each failed attempt (`$_.Exception.Message`), so the first person to see the log can tell "wrong URL" from "server down".
- **Verify a deactivation against the live endpoint, not just the database flag.** In n8n 2.x, `unpublish:workflow` flipped `active`/`activeVersionId` but the `webhook_entity` row stayed, and a probe still reported the path as registered after a restart. The probe (compare the message for a known-dead path) is the evidence; the flag is a claim.
- **Answer an ambiguous "how do I do X" with one clarifying question before a full recipe**, especially when X touches production config. A wrong recipe delivered confidently costs more than the question.
