1. **Two Claude Code sessions working in the same repo can both receive the same-shaped
   close command ("ปิด session /rrr") within a minute of each other**, and the handoff
   context injected into one session's system prompt can describe work that actually
   belongs to the other session. This is confusing to disambiguate without explicitly
   re-verifying against the session's own `.jsonl` — the surrounding CLAUDE.md/handoff
   context alone is not sufficient evidence of "what this session did."
2. **No second friction point beyond that** — the dig-miner ran cleanly on the first
   call and gave an unambiguous, small (4-line) result, so verification here was cheap
   once attempted. Padding this list further would be inflation, not honesty.

## Lessons Learned

1. **When a resumed session's injected handoff/context describes work that doesn't match
   what you'd expect from your own visible conversation history, verify against the
   session's actual `.jsonl` before writing a retrospective that blends the two** —
   especially in multi-session setups (MAW / multiple concurrent Claude Code sessions in
   one repo) where a sibling session's handoff can appear alongside an unrelated session's
   real history. The dig-miner subagent exists for exactly this kind of disambiguation,
   not only for reconstructing timelines lost to compaction.
