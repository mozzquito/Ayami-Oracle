## Lessons Learned

- When a per-agent focus/state file is documented as "overwrite on next task" (not append-only), treat any answer recorded only there as ephemeral — if the answer matters beyond the current task, it needs its own durable file the moment it's produced, not a pointer that assumes the focus file will still hold it later.
- Before reconstructing lost or unrecoverable analysis from adjacent artifacts (other agents' docs, other sessions' outputs), say "the original isn't recoverable, here's what I'm using instead" to the user *before* presenting the reconstruction — not folded into the reconstruction's own prose. The distinction between "recovered" and "substituted" matters for trust even when the substitute turns out better.
- When verifying a specific technical claim (a config key, a flag, a schema) against a CLI tool, start with that tool's own `--help`/`--version`/subcommand help output before broadening to a filesystem search — the narrow, first-party source is almost always faster and more authoritative than searching for config-shaped files nearby.
