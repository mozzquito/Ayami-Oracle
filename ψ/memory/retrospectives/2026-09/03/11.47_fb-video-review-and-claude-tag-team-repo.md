## Honest Feedback

Three friction points, specific to this session:

1. **The `/watch` skill's transcript-cleaning step is broken for prose.** `sed '/^[0-9]*$/d; /^$/d; /-->/d' | sed 's/<[^>]*>//g' | sort -u` alphabetizes and dedupes lines, which is fine for something like a config file but destroys narrative order in a spoken transcript. I redid it with `awk '!seen[$0]++'` to preserve order while still dropping exact-duplicate caption lines. This is a skill-definition bug, not a one-off mistake on my part, and will bite the next person who runs `/watch` on spoken content and doesn't happen to eyeball the output before using it.

2. **agy's headless permission wall cost two wasted round-trips.** Both attempts (file-read prompt, then an inlined-content prompt) hit the same `"no output produced — a tool required the 'command' permission"` failure. Neither attempt was informed by the fact that this exact failure mode is already documented in this Oracle's own memory. I should have checked `ψ/memory/learnings/` for agy quirks before the first attempt, not after two failures.

3. **Repo-scope ambiguity cost a clarifying round-trip.** When มอส first said "ต้องการ SETUP.md ใส่ใน repo ให้หน่อย" without naming a repo, I defaulted to placing it in the current repo (ayami-oracle) and asked for confirmation only implicitly by proceeding — มอส then had to correct me with "ต้อง repo ใหม่ได้เลย." ## Lessons Learned

1. **Before executing a skill's literal shell pipeline against prose/narrative content, mentally trace what the operation does to structure — not just whether it runs without error.** `sort` and `uniq -u`-style dedup logic are safe for unordered data (config lines, log lines) but silently destroy meaning in anything sequential (transcripts, chat logs, ordered instructions). Order-preserving dedup (`awk '!seen[$0]++'`) is the safe default for any pipeline that touches spoken/written narrative text.

2. **Before delegating to a sibling CLI agent with any known environment quirk (headless permission prompts, alias-in-background failures, etc.), check `ψ/memory/learnings/` for that agent's name first.** Repeating an already-documented failure costs a round-trip that a grep would have avoided — this generalizes beyond agy/zcode to any external tool this Oracle delegates to repeatedly.

3. **When a user asks for a deliverable to go "into a repo" without naming one, and earlier context already implied a dedicated/new repo, ask the new-vs-existing question explicitly before creating the file** — defaulting to the current repo and letting the user correct you costs the same round-trip as just asking, but reads as not having listened to the earlier framing.
