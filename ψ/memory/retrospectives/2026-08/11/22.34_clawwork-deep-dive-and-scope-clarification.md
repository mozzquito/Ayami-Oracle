## Lessons Learned

- Before running anything against a paid API key on a free/trial tier, check the actual balance/limit endpoint first (e.g. `GET /api/v1/key` for OpenRouter) rather than discovering the ceiling via a failed request — cheaper in both tokens and round trips.
- A tool whose description explicitly says "don't use me to poll background work" (like `ScheduleWakeup`) should never be reached for as a generic waiting mechanism, even under time pressure — re-read the tool's own guidance before invoking it if its name suggests a shortcut.
- When a third-party repo's helper scripts hardcode a specific environment manager (conda, a particular Node version manager, etc.), grep the script for that dependency *before* the first run rather than discovering it live — the fix is usually trivial once known, but knowing it up front saves a full round trip.
- Don't assume a dataset or resource is gated because of who published it (OpenAI, in this case) — try the direct public-access path first; GDPVal was fully open despite the framing suggesting otherwise.
- When explaining what a benchmarking/evaluation tool is *for*, lead with the boundary ("this measures X, it does not improve X") before any positive framing — users correctly get suspicious of ROI-flavored language around a tool that doesn't change the thing being measured, and it's cheaper to say the boundary first than to be pushed into saying it second.
