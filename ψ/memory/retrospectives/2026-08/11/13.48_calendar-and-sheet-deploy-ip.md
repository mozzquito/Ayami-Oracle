## Lessons Learned

- **เช็ค tool/capability availability ก่อนเสนอตัวเลือกให้ user เลือก** ไม่ใช่หลังจากเสนอไปแล้ว — โดยเฉพาะงานที่พึ่งพา external integration (browser extension connection, MCP tool coverage) ที่ไม่รู้จนกว่าจะลองเรียก
- **ไฟล์ที่มี credential จริง (password, connection string) ต้องหยุดถาม access-control confirmation ก่อนย้ายข้าม system boundary เสมอ** แม้ user จะสั่งมาตรงๆ ก็ตาม — ตรงกับ [[feedback_verify_before_asserting]] ในหลักการที่กว้างกว่า: ตรวจสอบก่อนเชื่อ/ก่อนลงมือในสถานการณ์ที่ reversible cost ต่ำแต่ privacy cost สูง
- **เมื่อพบว่าข้อมูลลับ (password) ซ่อนอยู่ใน field ที่ไม่ได้ชื่อ "password" ตรงๆ** (เช่น connection string ใน column note) — ต้อง redact ให้ครบ ไม่ใช่แค่ drop คอลัมน์ที่ชื่อ password เท่านั้น เพราะข้อมูลลับอาจแฝงอยู่ใน free-text field อื่น
