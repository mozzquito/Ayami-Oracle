## Lessons Learned

- When a skill's literal instructions assume one input shape (e.g. "clone via ghq") and the actual input doesn't fit (a blog URL, not a repo), say so out loud in one sentence before silently substituting a lighter-weight approach — even when the substitution is obviously correct. Silent adaptation is fine for the *action*; staying silent about *having adapted* is what creates ambiguity later.
- If a memory-save is offered and left unanswered, don't let it evaporate. Either follow up explicitly before moving to the next task, or default to saving anyway (per the project's own "Nothing is Deleted" principle) and let the user say to remove it — asymmetric cost of over-saving vs. losing a decision-relevant answer.
- For session retros spanning an overnight gap, report active engagement time in the header, not wall-clock span, and call out the gap explicitly — otherwise duration metrics silently mislead future pattern-detection (session-metrics.md).
