## Honest Feedback

Three friction points, specific to this leg:

1. **`timeout` is not a real command on this machine's default shell.** I wrapped a zcode call in `timeout 90 node ...` assuming GNU coreutils' `timeout` was available — it isn't on macOS zsh without `coreutils` installed (which would show up as `gtimeout`). Cost one full failed dispatch before I noticed the actual error message.
2. **zcode's footer-retry produced a completely empty, error-free output file.** No stack trace, no exit-code complaint in the log — just nothing. This is a 4th distinct zcode failure shape logged today (alongside 524 timeout ×3), and I didn't investigate it further since the task was small enough to just do myself.
3. **agy's `--mode plan` turned a "print the answer directly" instruction into a reviewable plan document requiring my own file-read to extract the content**, and silently dropped translation coverage on ~5 small text elements (3 sub-headings, the footer, 4 meta-labels) that I had to catch by comparing section-by-section against my own request rather than agy flagging the gap itself.

## Lessons Learned

- **A lesson-learned file written earlier in the same conversation doesn't apply itself.** Before repeating an action that a just-written lesson warns against, explicitly check whether the *new* situation differs at the level the lesson actually operates on (here: z.ai infra health, not task shape) — writing the lesson down is not the same as consulting it before the next relevant decision.
- **`timeout` (GNU coreutils) is not guaranteed on macOS zsh.** Don't wrap delegate-CLI calls in `timeout N ...` on this machine; use background dispatch + explicit polling instead, or verify `command -v timeout` first.
- **When instructing a delegate CLI to "print directly, don't write to a file," check the actual output for an unrequested review/plan wrapper** (e.g. agy's `--mode plan`) before assuming the literal answer was returned — read whatever artifact it did produce rather than treating an empty stdout as failure.
