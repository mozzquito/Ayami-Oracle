## Lessons Learned

- **When asked "does this look safe to delete" for multiple similar-looking targets in a row, don't let the verdict on the first one set the depth of scrutiny for the next** — surface structure (directory names, apparent project layout) can look identical between "empty scaffold" and "real active project"; the distinguishing signal (actual file count, git remote, recently-modified content) only shows up if you check it fresh each time rather than pattern-matching against the previous answer.
- **Prefer a reversible action (move to Trash) over permanent deletion (`rm -rf`) for any human-directed cleanup outside the repo**, even when the human said "delete" — the *word* they used doesn't change the actual reversibility cost of the action; a Trash move gives the same practical outcome (freed space, folder gone from view) with a recovery path if the "definitely safe" judgment turns out wrong.
