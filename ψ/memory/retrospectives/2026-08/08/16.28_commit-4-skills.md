## Lessons Learned

- **When a human's commit instruction names a specific, narrow set of files ("these 4 skills"), stage exactly that set — don't sweep in other pending changes just because they're sitting in the working tree, even if they were produced moments earlier by the same workflow.** Scope discipline on commits prevents silently bundling unrelated or not-yet-approved changes into one commit.
- **A skill invoked twice in quick succession for genuinely small, related events is a signal worth naming to the human** (e.g., "want me to fold this into the last retro instead of writing a new one?") rather than silently producing near-duplicate full-template output each time.
