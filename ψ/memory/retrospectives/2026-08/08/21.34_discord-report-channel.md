## Lessons Learned

- **Before attempting an API action on behalf of a service account (bot, service credential, etc.), check what permissions it actually has rather than attempting the call and handling the failure reactively** — a quick permission check up front (here: recalling the bot's OAuth scopes from earlier in the session) can save a failed API call and, more importantly, correctly route the task to whichever party (human or agent) can actually do it cheaply. Re-granting permissions through a painful auth flow is not always the cheaper path compared to a 30-second manual action.
- **Verification effort should scale with the actual risk surface of the change, not be applied uniformly** — a read-only, in-memory summary feature warrants a quick live test; a hardening change to a command-blocking security hook warrants an explicit test suite. Treating every change with maximum verification ceremony wastes time; treating every change with minimum verification risks the kind of regression found earlier tonight. The judgment call is in matching effort to risk, not picking one policy for everything.
