## Lessons Learned

- **Before declaring a service "ready" after starting it, check its actual readiness state (build artifacts, install markers) if the tool exposes one — a process starting cleanly is not the same claim as the feature being usable.** Applies to any `serve`/`start`/`run` command for a tool with a separate build/install step.
- **When a globally-linked CLI breaks, check the resolved symlink target before assuming reinstall-from-scratch is needed** — bun/npm global installs can point at ephemeral locations (`/tmp`, build caches); resolving the chain often reveals a one-line relink fix instead of a full reinstall.
- **A skill's automated flow (like `/learn`'s `ghq get -u`) can silently assume a dependency is present** — worth a quick `command -v <tool>` before running the flow's first external-tool step, rather than discovering the gap via a failed command mid-flow.
