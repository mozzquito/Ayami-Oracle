## Honest Feedback

1. **Two parallel `railway.json` configs is real ongoing friction.** Every deploy to either service
   requires remembering to `cp` the right file first — I did this correctly today, but it's a
   silent trap: a `railway up` with the wrong config swapped in would deploy successfully with no
   error, just the wrong service's behavior. This is exactly the shape of bug that bit us with the
   cronSchedule issue — no error surface, only symptom.
2. **`railway status`/CLI display for cron fields is now confirmed untrustworthy** — cost real
   debugging time before switching to raw GraphQL as ground truth. Should default to GraphQL
   verification for any Railway field going forward rather than trusting CLI output.
3. **The dashboard/production desync bug was structurally inevitable** given the "recompute fresh
   from `cloud_run.py`'s SYMBOLS" design — good that it was caught, but the same shape of bug (two
   places that must agree on strategy config) can recur anywhere else a value is duplicated instead
   of imported. Worth an explicit grep for other duplicated-constant risks in this codebase.

## Lessons Learned

- When a cloud platform's CLI status output and its actual server-side state can silently diverge
  (Railway `cronSchedule` today), never trust CLI display for anything safety/scheduling-critical —
  verify the specific field via the platform's API directly, and encode that verification into the
  deploy script itself, not just a one-time manual check.
- When two services must share config derived from the same source of truth (e.g. per-symbol
  strategy assignment), import the shared value directly rather than hardcoding or duplicating it —
  a hardcoded copy will desync silently the next time the source changes, with no error to catch it.
- Before adding a new derived/resampled time-series feature to a signal (e.g. weekly resample from
  daily bars), write an explicit lookahead test (perturb a specific future data point, assert past
  output is unchanged) rather than trusting that `.shift()` placement is correct by inspection —
  resample-then-reindex is a common silent lookahead trap.
- When a consulted second-opinion agent (agy/zcode equivalent) is reliable for structural/
  qualitative review but has been caught fabricating quantitative data multiple times, keep using
  it for the former and stop trusting it for the latter — don't discard the tool wholesale over one
  weak dimension.
