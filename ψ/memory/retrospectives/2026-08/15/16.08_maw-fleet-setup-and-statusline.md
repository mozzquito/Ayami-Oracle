**Friction 2 — `maw serve stop` gave a false negative.** It reported "already stopped"
while a process was still bound to the port (confirmed via `lsof`), forcing a manual

around cleanly except by dropping to `lsof` directly — worth remembering for next time
this tool is used, since the built-in stop/status commands can't be trusted at face
value.

**Friction 3 — the org search approach works but has a blind spot.** `gh api
search/code` finds exact keyword matches fast, but it can't tell me whether a match is
the *current best* answer versus an older/superseded one in the same org (e.g. `maw
token` vs. the `CLAUDE_CONFIG_DIR` approach — both are legitimate multi-account
solutions from the same org, at different levels of investment, and I had to judge which
one fit the ask rather than the search surfacing that judgment for me).

## Lessons Learned

- **Before passing a CLI flag you haven't used before, read its help text or doc comment
  first — especially on a persistent/daemon process** where a bad flag's effects
  (isolated state dir, wrong port, etc.) won't surface until several steps later and are
  expensive to trace back. A 10-second `--help` check would have prevented the whole
  `--as` detour in this session.
- **When a generated/wizard config sets a permission-bypass flag as its default
  (`--dangerously-skip-permissions`, `--yes`, `--force`, etc.), always read the generated
  file before first use and challenge that default** — wizards optimize for
  "it just works," not for safety, and the two are frequently in tension.
- **Don't trust a tool's own status/stop commands blindly when debugging a stuck
  daemon** — cross-check with the OS directly (`lsof -iTCP:<port>`, `ps`) before
  concluding a process is or isn't running; a tool's internal state tracking can drift
  from reality (missing PID file, wrong home dir, etc.).
- **For narrow, specific questions about a known org/monorepo, `gh api search/code`
  beats a full clone-and-explore** — it's faster and cheaper, and is the right default
  when the ask is "does X exist somewhere in here" rather than "help me understand this
  whole codebase."
