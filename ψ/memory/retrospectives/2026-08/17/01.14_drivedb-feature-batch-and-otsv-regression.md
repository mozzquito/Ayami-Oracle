## Lessons Learned

- When a delegation prompt specifies an exact CLI flag, config value, or API parameter as fact (not as "figure out the right flag"), verify that fact against the real tool/API first — a subagent will follow a wrong spec exactly as faithfully as a right one, and precision in the prompt doesn't substitute for correctness of the facts inside it.
- Delegated-agent report quality is not a reliable trust signal — treat every "done" claim as needing the same independent verification regardless of how detailed or thin the self-report reads, especially for protocol-level or network-dependent work where subtle correctness bugs (off-by-one byte offsets, wrong escape resolution, wrong stream-handling flags) don't show up unless you actually exercise the failure path for real.
- For any resumable/retryable operation (uploads, multi-step pipelines), the only convincing verification is to actually trigger the interruption for real (kill -9, not a code-level abort) and independently confirm partial state with the third-party system itself before trusting your own code's report of what happened.
- When a local AI/inference dependency (Ollama, local LLM servers, etc.) accepts connections but hangs on real work, check basic resource pressure (`vm_stat`, `ollama ps` for "is anything actually loaded") before assuming the calling code is at fault — a hang on a trivial request with nothing loaded is a fast, cheap signal that the problem is environmental, not logical.
- In autonomous/background-loop mode, stop the loop proactively once all established, user-authorized work is verified complete rather than let it idle — inventing further work (even reasonable-sounding next steps) without the user's direction oversteps the "steward, not initiator" boundary.
