## Lessons Learned

1. **When a user's own earlier answer explicitly names two possible interpretations
   ("X or Y, deliberately both"), a follow-up question touching that same ambiguity deserves an
   answer that addresses both branches, not a silent pick of one.** Defaulting to a single
   interpretation without naming the alternative quietly reintroduces the exact ambiguity that was
   supposedly already surfaced and left open.
2. **A `VARCHAR2` column pressed into service as a sort key for what is conceptually a
   date/time value is a real correctness risk, not just a stylistic note** — if the caveat is
   worth flagging at all, it's worth actually testing (e.g. `ORDER BY TO_DATE(col, 'format')` vs.
   raw string sort, compare a few rows) rather than leaving it as an unverified warning attached to
   a query the user may run as-is.
