## Lessons Learned

- When a delegated agent's API backend fails with the same specific error on two consecutive attempts at the same task, treat that as a strong signal to stop retrying identically and either reduce the task's size/complexity or take over the work directly — a quick trivial-request ping can distinguish "the service is fully down" from "this specific large request exceeds some infrastructure limit," and that distinction should inform which fallback makes sense.
- When two local services independently use hardware-accelerated inference on the same machine (e.g. a local Whisper transcription tool and a local LLM server like Ollama, both using the same GPU/unified-memory pool on Apple Silicon), a model left resident in memory by one can cause the other to fail with an out-of-memory error even when they aren't running literally simultaneously — "idle but loaded" is enough to cause contention. When designing a feature that triggers one such service automatically (e.g. auto-summarize), check whether the underlying API offers an explicit "don't keep this loaded" option (Ollama's `keep_alive: 0`) and use it for auto-triggered paths specifically, distinct from manually-invoked paths where staying warm is a legitimate convenience.
- Don't trust an estimated timeout value (even one endorsed by a careful design review) until it's been checked against real measured latency on the actual target machine — hardware-dependent operations like cold-loading a multi-gigabyte model can vary far more widely in practice (this session: 18s to 70+ seconds for the same model on the same machine) than a single test run would suggest, and a timeout tuned to one observation can still fail the next time.
- When a user interrupts an in-progress task with an unrelated question and then redirects back with a short instruction ("continue," "go ahead," "develop ได้เลย") before the unrelated question is ever answered, resume the original interrupted task rather than assuming the redirect implies the new question should be answered first or from memory — treat the interruption as shelved, not as a request queued for later, unless the user says otherwise.
