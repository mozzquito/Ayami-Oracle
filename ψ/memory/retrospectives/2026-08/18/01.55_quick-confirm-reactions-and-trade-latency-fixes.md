## AI Diary

The part of this stretch I keep coming back to is the agy `--cwd` mistake, because it's a clean
example of exactly the failure mode named in this morning's own lesson-learned file about verifying
facts before delegating. I set up two isolated git worktrees specifically to prevent zcode and agy
from colliding, felt good about the isolation plan, and then didn't actually check whether agy's
CLI supported the primary mechanism (`--cwd`) that the isolation depended on — I saw `--add-dir` in
the skill doc, assumed it was equivalent to zcode's `--cwd`, and moved on. It isn't. `--add-dir`
adds a directory to the workspace; it doesn't relocate where the agent operates from. The Bash
tool's cwd had drifted to the main repo from earlier commands, so agy just edited the real,
live `dashboard.py`.

What I'm actually pleased with is what happened *after* I noticed — I didn't panic-revert and
re-explain, I first checked whether the edit was actually bad (it wasn't — agy's code was correct,
just landed in the wrong place), then treated it as free information rather than pure damage: I had
two working implementations to compare instead of one, and merged the better parts of each by hand.
The mistake cost nothing in the end, but only because I checked `git status` before assuming
anything, not because the mistake was harmless by design.

[→ AGENT DECISION] I should have run `agy --help | grep -i cwd` (a 2-second check) before trusting
my assumption that `--add-dir` was agy's equivalent of zcode's `--cwd` — I had the tool available
and didn't reach for it until after the damage was already done, not before.

   back — that's real session overhead multiplying across a day with 4 separate zcode/agy

   zcode stays in the loop for time-sensitive questions or gets reserved for async/non-blocking
   ones.
2. **Redis password appeared in raw terminal output once** (`railway variables --kv` output
   included `REDIS_URL` with its embedded password because my grep filter only excluded
   `TOKEN|WEBHOOK`, not `REDIS_URL`). Caught it, didn't repeat the mistake, and nothing downstream
   (files, commits) captured it — but the fact that I filtered a specific list of "sensitive-looking
   var names" instead of defaulting to redacting anything with a URL-embedded credential pattern is
   the kind of narrow filter that will miss the next one too if I don't generalize the habit.
3. **Two isolated worktrees for a task this small was probably overkill in retrospect** — the
   actual feature (groupby + a new dashboard table) took each agent under two minutes to produce.
   The worktree setup/teardown (branch creation, `--cwd` per agent, cleanup) added more overhead
   than the task itself needed, and the isolation didn't even work for agy anyway. A simpler
   pattern for small, low-conflict-risk tasks might be: let one agent implement directly in a
   scratch file or a single throwaway branch, skip worktree ceremony entirely.

## Lessons Learned

- Before relying on a CLI flag to establish agent isolation (a working directory, a sandbox
  boundary, a permission scope), verify the flag does what you assume by checking `--help` or the
  tool's own docs directly — a flag with a similar-sounding name in a sibling tool (zcode's `--cwd`
  vs agy's `--add-dir`) is not guaranteed to behave the same way, and the isolation plan is worthless
  if its foundational assumption is wrong.
- When redacting secrets from command output before printing/logging, filter by *pattern*
  (embedded credentials in URLs, tokens matching known API-key shapes) rather than by a fixed list
  of "sensitive-sounding variable names" — a named-list filter silently misses anything whose name
  doesn't happen to contain one of the flagged words, even when its *value* is just as sensitive.
- When a delegated task lands in the wrong place by mistake but the actual content produced is
  correct, don't discard the work reflexively — verify what happened, confirm the content itself is
  sound, and treat it as usable input (even if the process around it needs fixing) rather than
  automatically re-doing everything from scratch.
