## Lessons Learned

1. **เมื่อ delegate งาน implementation จริง (ไม่ใช่แค่ review) ให้ CLI agent ภายนอก ห้ามเชื่อ exit message ของมันเลย ไม่ว่าจะ "สำเร็จ" หรือ "ล้มเหลว"** — ต้อง diff working tree กับ backup ก่อน-หลังเสมอ เพราะทั้งสองทางเป็นไปได้: มันอาจ "ล้มเหลว" ทั้งที่เขียนไฟล์จริงไปแล้วบางส่วน หรือ "สำเร็จเงียบๆ" หลังจากที่ดูเหมือนตายไปแล้ว
2. **`pkill -f "<tool> -p"` ไม่พอที่จะหยุด coding-agent CLI** — เครื่องมือพวกนี้มักสร้าง detached worker process (เช่น `zcode-cli`) ภายใต้ชื่อ process คนละแบบกับ invocation pattern ที่ใช้เรียกมัน ต้องเช็ค `ps aux` หา process จริงที่ยังกิน CPU อยู่ ไม่ใช่แค่ kill ตาม pattern ที่ใช้ตอนเรียก
3. **agy `--mode accept-edits` ในโหมด headless ยัง hard-block ทุก Bash/"command" permission call** — ใช้ได้จริงเฉพาะงานที่ทำได้ด้วย Edit/Write ล้วนๆ ไม่มี shell command เลย (แม้แค่ `mkdir`) ถ้างานต้องมี shell step ต้องเตรียมใจว่าจะ fail แบบไม่มี partial progress
4. **ก่อนยิง CLI agent ตัวใหม่ทับ directory เดียวกัน ต้องมั่นใจว่าตัวเก่า "ตายจริง" ทุก process ไม่ใช่แค่ wrapper** — สอง writer พร้อมกันบนไฟล์ชุดเดียวกันคือความเสี่ยง corruption จริง ไม่ใช่แค่ทฤษฎี (เกือบเกิดขึ้นจริงใน session นี้)
