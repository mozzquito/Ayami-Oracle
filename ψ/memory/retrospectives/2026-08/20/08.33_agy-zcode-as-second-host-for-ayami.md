## Lessons Learned

- เมื่อโปรเจกต์มีไฟล์ config มาตรฐานข้ามเครื่องมือ (เช่น `AGENTS.md`) อยู่แล้ว ให้ **ทดสอบ empirically ว่าเครื่องมืออื่นอ่านมันจริงไหม** ก่อนสรุปว่า "ต้อง setup เพิ่ม" — บ่อยครั้งที่ infra ข้ามเครื่องมือมีมาตรฐานร่วมอยู่แล้ว (SKILL.md format, AGENTS.md) และงานที่คิดว่าต้องสร้างใหม่ทั้งหมดกลายเป็นแค่ต้อง mirror ไฟล์
- ก่อนเชื่อว่า background job (`cmd &`) ใน bash tool จะ persist ผลลัพธ์ครบ ให้ตรวจด้วย `ps aux` หรือ poll ซ้ำก่อนสรุปว่า "ไม่ทำงาน" — ผลลัพธ์ที่ว่างเปล่าในรอบแรกอาจแปลว่า "ยังไม่เสร็จ" ไม่ใช่ "พัง"
- เขียนโค้ดหลายบรรทัด (โดยเฉพาะ heredoc/multi-line function) ลงไฟล์ที่ใช้งานจริงของผู้ใช้ (dotfile, config) ให้ **อ่านทวนเนื้อหาที่จะเขียนก่อน apply เสมอ** แม้จะมั่นใจว่าคิดมาถูกแล้ว — ต้นทุนของการพังใน dotfile จริงสูงกว่าใน scratch file มาก
- เมื่อ permission/safety classifier บล็อกซ้ำ ให้หยุดและอธิบายข้อจำกัดตรงๆ กับผู้ใช้แทนที่จะหาวิธีเลี่ยงต่อไปเรื่อยๆ — บล็อกที่เกิดซ้ำมักเป็นสัญญาณว่าวิธีที่เลือกมีความเสี่ยงจริง ไม่ใช่แค่ over-cautious
