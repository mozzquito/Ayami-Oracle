## Lessons Learned

1. **อย่าสร้างทฤษฎี root-cause จากการอ่านภาพ/วิดีโอเบลอเพียงอย่างเดียว** — ถ้าหลักฐานตั้งต้นมาจาก
   OCR-by-eye ที่ไม่ชัวร์ (โดยเฉพาะตัวเลข/วันที่ที่หน้าตาใกล้กัน) ต้องพูดระดับความมั่นใจให้ชัดตั้งแต่แรก
   และหาทางยืนยันกับแหล่งข้อมูล authoritative (เช่น DB จริง) ก่อนเสนอทฤษฎีทางเทคนิคที่ซับซ้อน —
   ทฤษฎีที่ "ฟังดูสมเหตุสมผลทางเทคนิค" ไม่ได้แปลว่าอิงจากข้อมูลที่แม่นจริง

2. **เวลาต้องตีความ raw SQL output ที่ user paste มาแบบไม่มี column header — ขอ header (`INFORMATION_
   SCHEMA.COLUMNS`/`ALL_TAB_COLUMNS`) พร้อมกับ data ตั้งแต่รอบแรกเลย** ไม่ใช่รอจนเดา mapping ผิดก่อน
   ค่อยขอทีหลัง จะประหยัด round-trip ได้เยอะ โดยเฉพาะกับตารางที่มี column เกิน 50-100 ตัว

3. **สำหรับ Always Encrypted (SQL Server) หรือ column-level encryption อื่นๆ — เช็ค column ที่เข้ารหัส
   ให้ครบตั้งแต่ต้น แล้วสร้าง query แบบ exclude-list ไว้เลย** แทนที่จะปล่อยให้ user เจอ error ซ้ำๆ
   ทีละ column เวลาขยาย scope ของ query (เช่นตอนเปลี่ยนจาก search REFERENCE_NO ไป search TRAVEL_DOC_NO
   ที่ดันเป็น encrypted column อีกตัว)
