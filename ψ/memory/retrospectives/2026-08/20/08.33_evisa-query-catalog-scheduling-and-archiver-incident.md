## Lessons Learned

1. **Before drafting a `/rrr` retrospective, check whether the current session already has one
   from earlier in the same session** (`ls` the day's retro folder, check the last rows of
   `session-metrics.md` for the current session ID) — do this as step zero, before writing
   anything, not as a mid-draft sanity check. A session that spans a `/rrr` invocation partway
   through is not a signal to re-cover the whole session; it's a signal to scope the new retro to
   what's genuinely new since the last one.
2. **When a fresh retro would substantially overlap an existing one for the same session, trim to
   the incremental new ground and cross-reference the existing file by name — don't re-narrate
   covered material "for completeness."** Re-narration is where duplicate lessons/metrics rows
   creep in.
