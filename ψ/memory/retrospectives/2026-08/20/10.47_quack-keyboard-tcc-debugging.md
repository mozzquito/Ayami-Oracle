## Lessons Learned

- บน macOS รุ่นใหม่ (Sequoia/Tahoe ขึ้นไป) การ sign แบบ ad-hoc (`codesign --sign -`) สามารถบล็อก Input Monitoring/Accessibility TCC prompt ได้แบบเงียบๆ — `tccd` จะปฏิเสธไม่ยอมเด้ง prompt เลยแทนที่จะ error ดังนั้นการไม่มี error ไม่ได้แปลว่าโค้ดถูก ควรเช็ค `codesign -dvvv` (มองหา `flags=0x2(adhoc)` และ `Internal requirements count=0`) ตั้งแต่ต้น ก่อนจะเริ่ม debug permission logic
- เวลา debug ปัญหา macOS TCC/privacy permission ให้รัน `log stream --predicate 'process == "tccd"'` สดๆ ระหว่างที่แอปขอ permission จริง — จะได้เหตุผลตรงตัว (เช่น "Failed to match existing code requirement", "does not allow prompting; returning denied") ซึ่งมีประโยชน์กว่าการเดาจาก return value ของ API ฝั่งแอปอย่างเดียวมาก
- การแก้ keychain trust store หรือติดตั้งไฟล์ลง shared system location (เช่น `/Applications`) เป็น action ที่ควรขอ user ก่อนลงมือ แม้อยู่ใน auto mode ที่เอนเอียงไปทาง "ลงมือก่อน" — safety classifier มักจะบล็อกอยู่ดี ขอก่อนจึงเร็วกว่าลงมือแล้วโดนบล็อกแล้วค่อยขอ
