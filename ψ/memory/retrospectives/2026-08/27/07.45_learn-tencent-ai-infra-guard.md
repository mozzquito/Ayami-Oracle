## Lessons Learned

- A memory whose conclusion is "stop doing X entirely, workarounds don't help" should be **checked against a targeted variant before being trusted as still valid** — environment/tool behavior can shift between sessions (or the original diagnosis can turn out to be narrower than stated), and blanket avoidance rules deserve one cheap re-test rather than indefinite deference. Applies generally to any prior "give up on tool Y" learning, not just agy.
- Before invoking a self-pacing/scheduling tool (`ScheduleWakeup`, cron-like primitives) mid-task, check whether the current task is actually the kind that tool is scoped for — "something is running in the background" is not by itself sufficient justification; the harness's automatic task-notification re-invocation already covers ordinary "wait for background work" without any extra tool call.
- When two sibling-agent consults (zcode/agy) give genuinely conflicting technical claims about the same tool's capability, report the disagreement explicitly in the written artifact rather than silently picking the more confident-sounding one — the discrepancy itself is signal worth preserving for whoever verifies it later.
