## Lessons Learned

- **When a request could plausibly mean either "the project's own convention for this word" or "something genuinely outside the codebase," ask before building** — a repo having its own internal `activity.log`/session-tracking pattern doesn't mean every request using similar words ("daily record," "history") refers to that pattern. Check whether the request is about the codebase/project at all before reaching for the nearest matching repo convention.
- **A calendar event's title describing a future action ("registration opens at X", "reminder: Y starts soon") is not evidence the underlying event was attended or even happened** — read event titles literally for what they assert, and treat the `start`/`end` fields as when the *reminder/registration-window* event was scheduled, not proof of outcome. Confirm actual outcomes with the user rather than presenting calendar data as settled fact.
- **`/rrr`'s dig-miner subagent's `ls -t .../*.jsonl | head -1` is not session-safe under concurrent Claude Code sessions in the same project directory** — it will return whichever `.jsonl` was most recently written across ALL sessions in that project, not necessarily the current one. The main agent should pass its own already-detected `SESSION_ID`/file path explicitly into the subagent's prompt (not have the subagent re-derive it via `ls -t`) whenever more than one session might be active against the same project directory. This is a repeat of a pattern already logged on 2026-08-08 — worth fixing at the skill level rather than re-discovering per session.
