## Lessons Learned

- **When a request is ambiguous, check what context is already visible before asking the user to disambiguate from scratch.** A session's own system-prompt context (recent commit log, git status, prior retros) often already narrows the space; building a clarifying question purely from imagination when directly relevant evidence is sitting in front of you wastes the user's turn and can read as not having done basic homework.
- **A worktree tool's "fresh" default branches from the remote tracking branch, not local `HEAD` — verify they're in sync before relying on isolation for a repo with unpushed local commits.** If local `main` is ahead of `origin/main`, a fresh-mode worktree will silently omit that work entirely rather than erroring, so check `git log origin/main..main` (or just `ls` the files you expect) before trusting the worktree contains what you think it does.
- **Not every file write needs git-worktree isolation — files a project's own convention deliberately keeps untracked (vault/retro files never `git add`ed) don't benefit from an isolate-then-merge flow, since there's nothing to merge back.** When an isolation guard blocks a write for this class of file, the fix is recognizing the write doesn't need isolation, not fighting the guard.
- **`nohup`-started long-running processes (like a Discord bot) don't survive a Mac sleep/restart** — if a user needs a service reachable from outside (e.g. from their phone) across hours, a bare `nohup` is not durable enough; offer `launchd`/`pm2` proactively once the underlying need ("I want to use this from anywhere, anytime") is clear, rather than waiting to be asked.
