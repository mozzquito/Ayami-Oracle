## Lessons Learned

- **When a fix corrects an in-session behavior (not a stored artifact), check whether the artifact already has it right before assuming a repo-wide bug** — here, the Discord bot's persona prompt already specified female pronouns correctly from an earlier session; only the current conversation's live behavior had drifted. Scope the fix to where it actually broke, not to everywhere the same class of thing could theoretically live.
- **Reuse an established automation pattern (auth, CLI invocation shape, prompt structure) across features in the same repo rather than inventing a parallel one** — `check-line.sh` reused `bot.mjs`'s exact `agy -p ... --model ... --mode plan` call shape, keeping one consistent "how Ayami talks to her quick-brain" convention instead of two slightly different ones.
- **When a user's message is genuinely ambiguous (nickname change vs. banter vs. serious request), say so in one line rather than silently picking the low-effort interpretation** — even when the guess turns out fine, surfacing the ambiguity costs one sentence and removes any doubt; silently resolving it is a habit that will eventually pick wrong on something that matters.
- **A structural environment constraint (like an always-on-top overlay terminal blocking screen capture) should be documented directly in the artifact that depends on it working**, not just remembered from a prior conversation — `check-line.sh`'s header comment now states the Ghostty-overlay constraint explicitly so it doesn't need re-discovering by whoever (human or Oracle) touches this script next.
