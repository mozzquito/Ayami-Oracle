## Lessons Learned

- **เช็ค process ที่ฟัง port จริง (`ss -tlnp`) ก่อนสันนิษฐานสถาปัตยกรรมจากคำตอบสั้นๆ ของ user** เช่น "ใช้ nginx" ไม่ได้แปลว่าไม่มี K8s/container อยู่เบื้องหลัง — ตัวเลข port ที่ผิดปกติ (เช่น 6443, 16443) คือสัญญาณที่ชัดกว่าคำอธิบายของ user เอง
- **ก่อนสรุปว่า host สองตัว (IP ต่างกัน) เป็นคนละเครื่อง ให้เทียบ output ของคำสั่ง read-only เดียวกัน (เช่น `ss`/`uname`/`hostname`) ก่อนฟันธง** — public IP กับ private IP อาจชี้ไปเครื่องเดียวกันได้เสมอในสภาพแวดล้อม NAT/cloud
- **เมื่อหา secret/key ไม่เจอ ให้ไล่ค้นทุกช่องทางที่มีเครื่องมือจริงให้ครบก่อน (local find, remote find, OS-level search index) แล้วค่อยสรุปว่า "ไม่เจอจริง"** แทนที่จะเดาทางลัดหรือรีบเสนอ "สร้างใหม่" ทันที — การยืนยันด้วยเครื่องมือสร้างความน่าเชื่อถือมากกว่าการเดา
- **wildcard cert (`*.domain.com`) ไม่ครอบคลุม apex domain (`domain.com` เปล่าๆ)** — เป็นความเข้าใจผิดที่พบบ่อย ต้องเช็ค SAN list เสมอก่อนบอก user ว่า cert ใช้ได้กับ domain ไหนบ้าง
- **Certificate object ใน cert-manager ที่ status Ready=True ไม่ได้แปลว่ากำลังเสิร์ฟ traffic จริง** — ต้องเช็คว่ามี Gateway listener/Ingress อ้างอิง secret นั้นด้วย ไม่งั้น cert อาจ "มีอยู่" แต่ "ไม่ได้ใช้งาน" เงียบๆ
