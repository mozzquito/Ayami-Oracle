## Lessons Learned

- **When documenting a service manager's crash-restart behavior (launchd `KeepAlive`, systemd `Restart=`, Docker restart policies, etc.) as a fact the user will rely on, verify it with an actual kill test before writing it down — recalling the correct semantics from documentation/training is not the same as confirming this specific configuration does what the docs say it should.** This is a specific instance of a broader, now-repeated pattern in this project: asserting claims about system behavior before checking them empirically.
- **When switching a long-running network service (any bot holding a persistent connection — Discord gateway, websocket, etc.) from an ad-hoc process to a supervised one, stop the old instance before starting the new one.** Two processes authenticating with the same bot token can both connect to the gateway and produce duplicate replies or connection churn; the brief offline gap this causes is the safer failure mode.
- **`launchd` user agents (`~/Library/LaunchAgents/`) only start at GUI login, not at raw system boot** — for a personal always-logged-in Mac this is usually fine, but it's a real gap worth stating plainly to the user rather than letting "runs persistently" imply more uptime guarantee than it delivers.
