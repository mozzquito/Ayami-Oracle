## Lessons Learned

- When a new instruction conflicts textually with an existing durable instruction (especially in
  a *global*, cross-project file like `~/.claude/CLAUDE.md`), surface the conflict and ask rather
  than resolving it silently in either direction — durable files are read by every future session,
  so a wrong silent guess compounds instead of being a one-off mistake.
- For "can I delete/uninstall X now that I use Y" sysadmin questions, check live system state
  (active context/daemon/binary provenance) before answering — the generic knowledge answer and
  the actual-machine answer can diverge in ways that matter (e.g., which store holds the CLI
  binary vs. which store holds the data).
- If a tool/daemon you'd want to audit (Docker Desktop's own VM here) isn't running, say so
  explicitly as an unverified gap rather than implying the check was complete.
