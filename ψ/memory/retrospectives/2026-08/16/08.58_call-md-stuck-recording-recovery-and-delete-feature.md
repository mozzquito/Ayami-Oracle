## Lessons Learned

- **A delegated "second opinion" agent's claim about existing code needs the same verification bar as the first agent's implementation** — don't relay "confirmed via file:line" claims from a read-only review agent without spot-checking the cited lines yourself, especially when the claim becomes part of what you tell the user as established fact.
- **Always independently re-run the project's own typecheck/build and read the real `git diff` after delegating implementation to a coding CLI agent (zcode/agy/etc.), regardless of how confident its self-report sounds** — this is the single highest-leverage verification step and it's cheap.
- **Treat general praise ("good job", "เก่งมาก") as distinct from explicit authorization for irreversible or visible actions** (git commit, restarting a user's live running app) — wait for an explicit verb naming the action, every time, even mid-loop.
- **Don't schedule a short poll-interval wakeup right after launching a `run_in_background` Bash/Agent call** — the harness delivers a task-notification automatically; a manual short ScheduleWakeup right after is redundant and against the loop's own guidance.
