## Lessons Learned

1. **MAC-vendor OUI lookup เป็นแค่ triage heuristic ไม่ใช่หลักฐานยืนยันตัวตนอุปกรณ์** — เวลาไล่หาอุปกรณ์เฉพาะทาง (IoT/AI box) บนวงแลน อย่า dismiss ผลลัพธ์ vendor ที่ฟังดูแปลกหรือไม่คุ้นเคย (เช่น "Pinhole (Beijing) Technology") เพื่อไปเชื่อ vendor ที่คุ้นเคยกว่า (เช่น Hikvision) — ให้ยืนยันด้วยการเปิดเว็บ UI จริงของ IP นั้นก่อนสรุป

2. **macOS raw-socket network tools (nmap/arp-scan/tcpdump) พังแบบไม่ชัดเจนเพราะ TCC Local Network permission ไม่ใช่เพราะ sudo ไม่พอ** — เจอ error กำกวมแบบ `dnet: Failed to open device en0` ให้เช็ค System Settings > Privacy & Security > Local Network ของ terminal app ก่อนไปทางอื่น

3. **เจอ "feature ใช้บน Mac ไม่ได้" (plugin/ActiveX-style block) ในหน้าเว็บจัดการอุปกรณ์ — เช็คว่ามีเอกสาร HTTP/WebSocket API แนบมากับอุปกรณ์ก่อนเสียเวลาไปกับ VM/spoof UA** อุปกรณ์ประเภทนี้ (surveillance/AI box จากจีน) มักมี backend ที่ platform-agnostic เต็มรูปแบบ ตัว plugin block เป็นแค่เช็คที่ frontend เท่านั้น — คุยตรงกับ API เร็วกว่าและยั่งยืนกว่า

4. **credential ที่ใส่ทั้งใน URL field และ username/password field แยกในฟอร์มเดียวกัน มักชนกันจนพัง auth** — ถ้า device config form มีทั้งสองแบบ ให้ใส่ credential แค่จุดเดียว (เชื่อฟิลด์ username/password แยกเป็นหลัก) ไม่ใช่ทั้งคู่
