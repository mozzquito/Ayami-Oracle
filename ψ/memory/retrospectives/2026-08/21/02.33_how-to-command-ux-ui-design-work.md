## Lessons Learned

- **เมื่อบั๊กเดิม recur ซ้ำๆ หลาย fix ไม่เคยหยุดมันได้จริง ให้สงสัยว่า fix ที่ผ่านมาแก้ผิดจุด** — ในที่นี้ทุก fix ก่อนหน้าอุดรูรั่วที่ subagent แต่ไม่เคยเช็คว่า main agent เองก็มีรูรั่วเดียวกัน ต้องดูทั้ง call chain ไม่ใช่แค่จุดที่เพิ่งเจอบั๊กล่าสุด
- **ก่อนเขียนโค้ด heuristic เพื่อเดาค่าที่ระบบน่าจะมีให้อยู่แล้ว (เช่น session id ปัจจุบัน) ให้เช็ค environment variables ก่อนเสมอ** — `ls -t` เป็น heuristic ที่พังได้ง่ายเมื่อมี concurrent process หลายตัว ในขณะที่ `$CLAUDE_SESSION_ID`/`$CLAUDE_CODE_SESSION_ID` มีให้ใช้ตรงๆ อยู่แล้วโดยไม่ต้องเดาเลย — pattern นี้ใช้ได้กับกรณีอื่นด้วย: ก่อนเขียน derivation logic ที่ซับซ้อน ให้เช็ค `env` ก่อนว่ามีของสำเร็จรูปให้ใช้อยู่แล้วหรือเปล่า
- เซสชันเล็ก/สั้นไม่จำเป็นต้องยัด friction/lesson ให้ครบจำนวนตามฟอร์แมต ถ้าของจริงมีน้อยกว่านั้น หรือมากกว่านั้นก็ตาม — เขียนตามสิ่งที่เกิดขึ้นจริง
