## Lessons Learned

- When a fresh document or delegated-agent claim contradicts something already empirically observed earlier in the *same* session, treat the empirical observation as higher-confidence by default and re-verify the new claim — don't let recency alone decide which source wins.
- Two delegated sibling-agent (zcode/agy) calls on related questions within one session have no memory of each other — a later call's answer contradicting an earlier, already-agreed answer from the same agents is not automatically an update; it may just be a stateless re-derivation that missed context the earlier call had. Read both side by side before adopting either one's newest claim.
- An artifact published before a session fork/resume may lose update rights across that boundary — if referencing or updating an artifact from before a fork, spot-check the URL resolves (a cheap WebFetch) before assuming ownership carried over, rather than discovering the 404 via a failed publish call.
- A lesson written to `ψ/memory/learnings/` after a delegated-agent failure is worth re-reading and actually applying the next time the same tool is invoked in a later session — this session is direct evidence it works: the agy Session Activity block was fixed on the first retry because the earlier lesson was recalled and applied, not re-discovered from scratch.
