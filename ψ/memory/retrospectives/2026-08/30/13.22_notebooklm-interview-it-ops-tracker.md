## Lessons Learned

- เมื่อ browser automation tool คืน error เดิมซ้ำหลายรอบ (>3 ครั้ง) โดยไม่มีข้อมูลใหม่ ควรหยุด blind-retry แล้วเปลี่ยนไปเก็บ diagnostic เพิ่ม (เช่นดู process, ดู extension settings page) ก่อน retry รอบถัดไป — retry เฉยๆ ไม่ช่วยถ้า root cause ไม่เปลี่ยน
- เวลาสร้างตาราง/รายงานที่ต้องอนุมานข้อมูลบางส่วนจากแหล่งข้อมูลอ้อม (เช่น mapping severity/owner จากบทสนทนาที่ไม่ได้พูดตรงๆ) ให้ติด provenance marker แยกจากข้อมูลยืนยันแล้วเสมอ ไม่ปล่อยให้ผู้ใช้เข้าใจผิดว่าทุกอย่างเป็นข้อเท็จจริงจากต้นฉบับ
- คำสั่งสั้นๆ ที่แทรกกลางงานอื่น (เช่น "save ไว้ใน X") มักอ้างอิงถึง "งานที่เพิ่งทำเสร็จ" ไม่ใช่งานที่กำลังรันอยู่ ณ ขณะนั้น (ในเคสนี้คือ artifact ก่อนหน้า ไม่ใช่ retro ที่กำลังเขียน) — เช็ค context ล่าสุดก่อนอนุมานเป้าหมายของคำสั่งสั้น
- เมื่อ Google Sheet หรือ external doc มีคอลัมน์ที่ user ยังไม่ได้กรอก (เช่น Task Category ว่างทั้งคอลัมน์) การเสนอ taxonomy ที่ยึดโครงสร้างที่ user คุ้นเคยอยู่แล้ว (ในเคสนี้คือ DBA/Infra/Incident ที่ NotebookLM แบ่งไว้ตั้งแต่ต้น) ทำให้ user ตัดสินใจเร็วกว่าคิด taxonomy ใหม่จากศูนย์
