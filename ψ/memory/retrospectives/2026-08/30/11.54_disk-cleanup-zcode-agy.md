## Lessons Learned

- When a skill doc makes a specific technical claim about tool behavior ("X works in foreground, fails in background"), treat it as a hypothesis to re-check in the current session rather than a fact to build on directly — environment state (shell init, `.zshrc` sourcing) can invalidate a previously-true claim without the doc being updated.
- Before any destructive disk cleanup (VM bundles, container disk images, app caches), always verify the owning process/service isn't actively running first (`pgrep`, `<tool> status`) — confirmed absence of live state removes the need to ask "are you sure" per-item and lets deletion proceed directly once the user has approved the tier.
- When a delegated CLI agent (agy, zcode) can't run headlessly due to permission gating, don't escalate to skip-permission flags reflexively — try once, and if a second reasonable attempt is also blocked, drop it and proceed with whatever independent analysis is available rather than burning more turns chasing one tool.
