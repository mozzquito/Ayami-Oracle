## Honest Feedback

1. **MCP mid-session reload gap** — friction ใหญ่สุดของเซสชันนี้ ฉันสมมติ (ไม่ได้ตรวจสอบ) ว่า `/mcp` menu ที่กำลังเปิดอยู่จะ refresh รายชื่อ server ใหม่ทันทีหลังจาก `claude mcp add` แต่จริงๆ ต้อง restart Claude Code ก่อน ทำให้มอสต้องเจอ error เปล่าๆ ("mcp ไม่มี cloudflare-bindings") ก่อนที่ฉันจะวินิจฉัยถูก

2. **wrangler package conflict ไม่คาดฝัน** — ตอน `npm install -g wrangler` ครั้งแรก เจอ `EEXIST` เพราะแพ็กเกจ legacy `@cloudflare/wrangler` (ชื่อคนละอันกับ `wrangler` ตัวใหม่) ครองไฟล์ binary เดิมอยู่ ต้องเพิ่มขั้นตอน uninstall ก่อน ซึ่งไม่ได้อยู่ในแผนตอนแรก — เพิ่มรอบ round-trip โดยไม่จำเป็นถ้าเช็ค `npm ls -g` ก่อนตั้งแต่ต้น

3. **Skill tool ไม่ได้รัน zcode ให้อัตโนมัติ** — ตอนเรียก `/zcode` ผ่าน Skill tool มันแค่โหลด markdown คำสั่งของ skill กลับมา ไม่ได้รัน CLI จริง ต้องมาสั่ง Bash เรียก `zcode -p ...` เองอีกที เป็นขั้นตอนที่ไม่ obvious ในตอนแรก (แม้จะรู้จาก memory ว่า skill นี้ต้องแปลงเป็น Bash call ก็ตาม)

## Lessons Learned

- เวลาต่อ MCP server ใหม่ผ่าน `claude mcp add` ระหว่างเซสชันที่กำลังเปิดอยู่ ต้องบอกผู้ใช้ทันทีว่า "server ใหม่จะไม่ปรากฏใน `/mcp` จนกว่าจะ restart Claude Code" — อย่ารอให้ผู้ใช้เจอปัญหาเองก่อนแล้วค่อยวินิจฉัย
- ก่อนแนะนำ MCP server แบบ "ครอบคลุมทุกอย่าง" (endpoint/tool count สูงมาก) ให้ชั่งน้ำหนักกับ context budget ก่อนเสมอ — เลือกตัวที่เจาะจงตาม use case จริงจะปลอดภัยกว่าเป็นค่าเริ่มต้น
- ก่อนอัปเกรด CLI tool ที่เจอว่าเป็น deprecated version ให้เช็ค `npm ls -g` หรือเทียบเท่าก่อนว่าถูกติดตั้งด้วยชื่อแพ็กเกจเก่าคนละชื่อกับตัวใหม่หรือไม่ (เช่น `@cloudflare/wrangler` vs `wrangler`) จะได้ไม่เจอ `EEXIST` กลางทาง
