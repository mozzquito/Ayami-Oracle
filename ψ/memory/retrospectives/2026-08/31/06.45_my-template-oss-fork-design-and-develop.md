save was real, but it was closer to luck-plus-habit than to a designed safeguard.

## Lessons Learned

- **When implementing a design that was reviewed abstractly (by another model or in a
  separate pass), re-verify every load-bearing assumption against the real target
  codebase before treating the review as final** — an external reviewer's sign-off is
  only as good as what it could see, and it couldn't see the real repo.
- **Before copying a scaffold/draft file into a real target location, always `git
  status`/`ls` the destination first, even when confident it's new** — "I already
  checked this doesn't exist" from an earlier, different investigation is not the same
  guarantee as checking right before the write.
- **In a codebase with meta-tests enforcing naming conventions or ownership maps by
  static analysis (substring matches on generated code, hand-maintained ownership
  tables), budget extra discovery time for any rename or table-shape change** — the
  blast radius is larger than a plain grep for the old name suggests, because some
  references are structural (test assertions about *counts* of matching functions, not
  just occurrences of a string).
- **When a delegated CLI tool fails with a generic, non-specific error, stop varying
  parameters after 1-2 retries and switch strategy (e.g. inline content instead of file
  path) rather than continuing to guess which flag caused it** — isolating the true
  variable can cost more turns than just routing around the failure.
