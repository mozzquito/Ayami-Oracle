## Lessons Learned

1. **Oracle requires an unqualified `*` to appear alone in a SELECT list — mixing it with a named
   column requires a table-qualified wildcard (`t.*`), unlike MySQL/Postgres which allow a bare `*`
   alongside named columns.** When correcting a different SQL syntax error (e.g. a missing comma)
   by reconstructing a SELECT list that combines specific columns with `*`, explicitly check this
   rule before handing the "fixed" query back — don't assume a syntactically-plausible-looking fix
   is dialect-correct just because it addresses the original error message.
2. **A correlated `MAX(id)`-per-parent subquery pattern, once established as correct for one query
   shape (e.g. "the latest resolved application record"), does not automatically generalize to a
   different query shape asking a different question (e.g. "does this specific named document
   exist").** The same SQL pattern that's the right tool for "give me the current state" is actively
   wrong for "does X exist anywhere in the history" — re-derive whether the MAX/latest-only scoping
   is actually wanted for the specific question being asked, rather than reusing a working pattern
   from earlier in the same session by default.
3. **When correcting the same class of user error more than twice in a row, state the general rule
   once clearly and explicitly** (not just re-fix each instance silently) **— but if the same error
   recurs after that, don't assume the explanation didn't land; ask directly whether something about
   the editing workflow is causing it to drop out** (e.g. editing a saved draft that still has the
   old text, copy-pasting from an earlier message). Simply repeating the same correction with the
   same explanation a fifth time is unlikely to be more effective than the third.
