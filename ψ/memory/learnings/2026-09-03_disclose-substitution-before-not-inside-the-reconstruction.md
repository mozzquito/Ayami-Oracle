# Disclose substitution before, not inside, the reconstruction

Asked to "สรุป" (summarize) an earlier memory-architecture evaluation thread. The actual saved answer (an agy second-opinion consultation on `psi-memory-lab` priority) turned out to be unrecoverable — it lived only in a per-agent focus file (`ψ/inbox/focus-agent-agy.md`) that gets overwritten on the agent's next task by design, per this project's own Session Activity convention. Rather than report the loss, I read six same-day `/learn --fast` overview docs on the same repos and synthesized a decision doc from those instead — which was fine, and arguably more rigorous than the lost answer would have been. But the disclosure that this was a *substitution*, not a *recovery*, landed inside the written decision doc's own prose ("this doc reconstructs the decision... its actual answer was never saved anywhere findable"), not in the conversational hand-off to the user before presenting the summary.

**Why it matters**: the user can't tell the difference between "I found what agy said" and "I rebuilt something better from what was lying around" unless told which one happened, and the distinction changes how much weight the summary deserves. Quality of the substitute doesn't excuse skipping the disclosure — it just makes skipping it easier to not notice, because the result looks fine either way.

**How to apply**: the moment an intended source turns out to be gone, say so as the *first* sentence back to the user ("couldn't find X — here's what I did instead"), before doing the actual reconstruction work. Don't let a good substitute's quality stand in for the disclosure that a substitution happened at all.
