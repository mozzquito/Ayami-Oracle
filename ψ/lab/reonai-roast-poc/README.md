# ReonAI Roast POC

พิสูจน์ก่อนว่า "AI ช่วยคั่ว" ได้ผลจริงไหม ก่อนจะคิดเรื่องทำขาย — ตามความเห็นของ
zcode/agy ที่วิเคราะห์โมเดลธุรกิจไว้: จุดขายจริงคือซอฟต์แวร์ควบคุม (retrofit kit)
ไม่ใช่ตัวเครื่องคั่ว แต่ก่อนจะลงทุนทำ kit ขาย ต้องพิสูจน์ก่อนว่าการอ่าน
DT/HT/RoR + คุมแบบมีระบบ ให้ผลคั่วสม่ำเสมอกว่าคั่วมือจริงไหม

โปรเจกต์นี้คือบอร์ด ESP32 ราคา ~526 บาท (ตามที่เช็คราคาไว้) ติดเพิ่มบนเครื่องคั่วมือสอง
ที่มีอยู่แล้ว — **ไม่ต้องสร้างดรัม ไม่ต้องซื้อเครื่องใหม่**

## ขอบเขตของ POC นี้ (จงใจทำแค่นี้)

- **โหมด Monitor (default):** อ่านอุณหภูมิ DT (เมล็ด/ดรัม) กับ HT (ฮีตเตอร์) log กราฟ
  RoR สด ผ่านเว็บ ไม่แตะฮีตเตอร์เลย — ใช้คู่กับการคั่วมือปกติ เพื่อเก็บข้อมูลเทียบ
- **โหมด Manual duty:** คนตั้ง duty cycle ของ SSR เองผ่านเว็บ (ไม่ใช่ auto-control) —
  ใช้ทดสอบว่าวงจร SSR ทำงานถูกต้องเท่านั้น
- **ยังไม่มี** closed-loop / AI auto-control ในเวอร์ชันนี้ — ตามลำดับที่ zcode แนะนำ:
  พิสูจน์ก่อนว่าคุ้มจะทำขั้นต่อไปไหม

## ⚠️ Safety — อ่านก่อนต่อไฟจริง

**บอร์ดนี้มีแค่ software cutoff (ตัดที่ 260°C) เป็นเกราะสำรอง ไม่ใช่ตัวหลัก**
ก่อนต่อ SSR เข้าฮีตเตอร์จริง (220V/1000W) ต้องมี:

1. **สวิตช์ตัดความร้อนเชิงกล (bimetal thermal cutoff / thermal fuse)** ต่ออนุกรมกับ
   สายไฟฮีตเตอร์ฝั่ง mains แยกจาก ESP32 โดยสิ้นเชิง — ถ้าซอฟต์แวร์ค้างหรือ SSR ช็อตค้าง
   ตัวนี้ต้องตัดไฟได้เองโดยไม่พึ่งโค้ดเลย
2. **สายดิน** ต่อกับตัวเครื่อง/โครงโลหะ
3. **พัดลมต้องเป่าต่อหลังปิดฮีตเตอร์** อย่าตัดพัดลมพร้อมฮีตเตอร์ทันที
4. ห้ามปล่อยเครื่องทำงานโดยไม่มีคนเฝ้า
5. ตรวจสอบ spec แรงดัน trigger ของ SSR-40DA รุ่นที่ซื้อจริงก่อนต่อ GPIO 3.3V ตรงๆ
   — บาง SSR ต้องการกระแส trigger สูงกว่าที่ GPIO จ่ายได้ ถ้าไม่ชัวร์ใช้ทรานซิสเตอร์ช่วยขับ

ถ้ายังไม่มีข้อ 1 **ให้ใช้แค่โหมด Monitor เท่านั้น** อย่าต่อ SSR เข้าฮีตเตอร์จริง

## รายการที่ต้องซื้อ (เช็คราคาไทยไว้แล้วผ่าน agy, ~2026-09)

| ชิ้น | ตัวอย่างรุ่น | ราคาที่เจอ |
|---|---|---|
| บอร์ดคุม | ESP32 DevKitC V4 (USB-C) | ~179 บาท |
| SSR คุมฮีตเตอร์ | SSR-40DA 40A | ~129 บาท |
| หัววัดอุณหภูมิ x2 | MAX6675 + K-type thermocouple | ~109 บาท/ชุด (218 บาท x2) |
| **รวม electronics** | | **~526 บาท** |

ยังไม่รวม: สาย jumper, breadboard/perfboard, กล่องใส่บอร์ด (กันความร้อน/ควัน),
ฮีตซิงก์สำหรับ SSR (แนะนำ ถ้าจะรันไฟยาว)

## Wiring (ESP32-S3-DevKitC-1)

```
MAX6675 #1 (DT — bean/drum probe)      MAX6675 #2 (HT — heater probe)
  VCC -> 3.3V                            VCC -> 3.3V
  GND -> GND                             GND -> GND
  SCK -> GPIO12  (ใช้ร่วมกัน)              SCK -> GPIO12
  SO  -> GPIO13  (ใช้ร่วมกัน)              SO  -> GPIO13
  CS  -> GPIO14                          CS  -> GPIO21

SSR-40DA control input (+) -> GPIO10   (เช็ค trigger voltage ก่อน! ดู Safety ข้อ 5)
SSR-40DA control input (-) -> GND

Fault LED (ภายนอก, ต่อผ่านตัวต้านทาน ~330Ω) -> GPIO11 -> GND
```

**ทำไมเลี่ยงขาพวกนี้บน S3:** GPIO19/20 คือ native USB (D-/D+) ของชิปเอง ใช้ไปแล้วสำหรับ
serial monitor — ห้ามเอาไปต่ออย่างอื่น, GPIO0/3/45/46 เป็น boot-strapping pin,
GPIO26-37 บางบอร์ดใช้เชื่อม PSRAM แบบ octal อยู่แล้ว (ขึ้นกับรุ่นบอร์ด), GPIO48
บนบอร์ด S3 DevKitC-1 ส่วนใหญ่คือ LED RGB แบบ WS2812 ไม่ใช่ LED ธรรมดาที่ digitalWrite
ได้ตรงๆ เลยใช้ LED แยกต่อเองแทน

ถ้ามอสมีบอร์ด ESP32 ธรรมดา (ไม่ใช่ S3) ในอนาคต ต้องเปลี่ยน `board` ใน `platformio.ini`
กลับเป็น `esp32dev` และตรวจขา GPIO ใหม่อีกรอบ (S3 กับ ESP32 ธรรมดามีขาที่ต้องเลี่ยงคนละชุด)

ตำแหน่งติดหัววัด: DT ให้ปลายหัววัดอยู่ในมวลเมล็ด/ใกล้ดรัมเหมือนเครื่องคั่วจริง, HT
ให้อยู่ใกล้แหล่งความร้อน (ไม่แตะโลหะฮีตเตอร์โดยตรงถ้าเกินสเปกหัววัด)

## Build & Flash

ใช้ [PlatformIO](https://platformio.org/):

```sh
cd ψ/lab/reonai-roast-poc
cp include/secrets.h.example include/secrets.h   # ใส่ WiFi จริง หรือปล่อยว่างให้ fallback เป็น AP
pio run --target uploadfs   # อัพโหลดหน้าเว็บ (data/) ขึ้น LittleFS ก่อน
pio run --target upload     # flash firmware
pio device monitor          # ดู log / IP ที่ต่อได้
```

ถ้าไม่มี WiFi ที่ตั้งไว้เชื่อมได้ภายใน ~12 วินาที บอร์ดจะเปิด access point ชื่อ
`ReonaiRoastPOC` (รหัส `roastpoc123`) แทน — ต่อมือถือ/โน้ตบุ๊กเข้า AP นั้นแล้วเปิด
`http://192.168.4.1/` ได้เลย เหมาะกับตอนไปออกบูธที่ไม่มี WiFi ให้ใช้

## วิธีทดสอบ (protocol ที่ zcode แนะนำ)

1. ติดบอร์ดบนเครื่องคั่วมือสอง ต่อแค่หัววัด 2 ตัว (โหมด Monitor เท่านั้น — ไม่ต้องต่อ SSR
   ในรอบแรกก็ได้ ถ้ายังไม่มี hardware cutoff)
2. คั่วโปรไฟล์เดิมซ้ำ 20-30 รอบด้วยมือตามปกติ กด **Start logging** ทุกรอบ ตั้งชื่อ
   session ให้จำได้ (เช่น `yellow-bourbon-01`) พร้อมกรอก **bean type / roast level /
   target °C** ในช่องข้างๆ ก่อนกด — ค่าพวกนี้จะถูกเขียนซ้ำในทุกแถวของ CSV ให้เอง
   (ตาม schema ที่ zcode แนะนำ) ทำให้ทีหลังเอาไฟล์หลายๆ รอบมา group/เทียบกันตามพันธุ์เมล็ด
   หรือระดับการคั่วได้โดยไม่ต้องมีไฟล์ metadata แยก
3. หลังคั่วแต่ละรอบ กด **Stop logging** แล้วโหลดไฟล์ CSV มาเก็บไว้ใน `analysis/logs/`
4. ถ้ามีเครื่องวัดสี (Agtron หรือเทียบสีมือ) บันทึกคะแนนแต่ละรอบลงไฟล์
   `analysis/agtron.csv` (คอลัมน์ `file,agtron`)
5. รันสรุปผล:
   ```sh
   python3 analysis/compare_roasts.py analysis/logs/*.csv --agtron analysis/agtron.csv
   ```
6. ดูค่า **coefficient of variation ของ time-to-193°C** — ยิ่งต่ำยิ่งสม่ำเสมอ เทียบกับ
   ความสม่ำเสมอที่คั่วมือทำได้เองปกติ (จากประสบการณ์ ไม่ใช่ตัวเลขที่ script คำนวณให้)

**เกณฑ์ตัดสิน (ตามที่ zcode เสนอ):** ถ้าเทียบ 20-30 รอบแล้วแยกไม่ออกจากการคั่วมือที่
เก่งอยู่แล้ว — โปรเจกต์นี้เป็นของเล่นที่ดี ไม่ใช่ธุรกิจ ถ้าสม่ำเสมอกว่าชัดเจน — ค่อยคิด
เรื่องทำ manual-duty→closed-loop control และแพ็คเป็น retrofit kit ขายจริง

## API (สำหรับต่อยอด/debug)

| Endpoint | Method | หน้าที่ |
|---|---|---|
| `/` | GET | หน้าเว็บ dashboard |
| `/api/state` | GET | snapshot ปัจจุบัน (JSON) |
| `/api/events` | GET (SSE) | stream สถานะสด ~1Hz |
| `/api/control` | POST | `{"mode":0\|1,"duty":0-100}` |
| `/api/reset` | POST | ล้าง fault (ทำได้เมื่ออุณหภูมิกลับมาต่ำกว่า cutoff แล้วเท่านั้น) |
| `/api/log/start?name=...&bean_type=...&roast_level=...&setpoint_c=...` | POST | เริ่มบันทึก session ใหม่ (`bean_type`/`roast_level`/`setpoint_c` เป็น optional แต่แนะนำให้ใส่ทุกครั้ง — ถูกเขียนซ้ำในทุกแถวของ CSV) |
| `/api/log/stop` | POST | หยุดบันทึก |
| `/api/log/list` | GET | รายชื่อไฟล์ log ที่มี |
| `/api/log/download?file=...` | GET | โหลดไฟล์ CSV |
